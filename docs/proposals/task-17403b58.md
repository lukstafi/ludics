## Item 1: CI lint for CLI help vs README drift

**Problem:** The `USAGE` constant in `src/index.ts` (lines 83-212) lists ~60 commands. The README CLI Reference section (lines 290-363) is a curated subset. These can drift silently.

**Approach:**
- Add a script `scripts/lint-cli-readme.ts` that:
  1. Extracts command names from the `USAGE` constant (parse lines matching `^\s+\w+`)
  2. Extracts command names from the README `## CLI Reference` section
  3. Reports README commands not present in USAGE (stale docs) as errors
  4. Optionally warns about USAGE commands missing from README (undocumented) as warnings
- Add a CI step in `.github/workflows/ci.yml` that runs `bun run scripts/lint-cli-readme.ts`
- The script exits non-zero on errors (stale docs), zero on warnings-only

**Files:** `scripts/lint-cli-readme.ts` (new), `.github/workflows/ci.yml`

## Item 2: Pure `startSessionsAutonomy` for testability

**Problem:** `evaluateAutoStartDecision` (line 902 of `src/mag.ts`) calls `startSessionsAutonomy()` internally, which reads `config.yaml` via `loadConfigSync()`. This makes unit testing require filesystem fixtures.

**Current state:** A pure variant `evaluateAutoStartDecisionPure` already exists (line 879) and is called by the non-pure wrapper. The wrapper reads config and resolves the slot.

**Approach:**
- The pure function already exists and is exported. The remaining improvement is to make the non-pure wrapper also exported (or remove it in favor of callers using the pure version directly).
- The single caller is the `auto-start-evaluate` CLI command (line 2756). Refactor it to call `evaluateAutoStartDecisionPure` directly, passing `startSessionsAutonomy()` and slot lookup as explicit arguments.
- Remove the private `evaluateAutoStartDecision` wrapper since it adds no value beyond the pure version.
- Add a unit test for `evaluateAutoStartDecisionPure` covering each autonomy level.

**Files:** `src/mag.ts`, `src/mag.test.ts`

## Item 3: Audit legacy adapter references

**Problem:** `launchSessionFromNotification` accepts a `rawAdapter` parameter and normalizes it via `normalizeLaunchAdapter`. All new-format callers already pass `"t3code"` literally. Legacy-format callers extract the adapter from notification text and pass it through normalization.

**Current state:** Legacy adapter references exist in:
- `src/mag.ts`: `normalizeLaunchAdapter`, `launchSessionFromNotification` signature, legacy launch/followup regex matchers (lines 1110-1139), doctor output (lines 1769-1772)
- `src/adapters/agent-claude.ts`, `src/adapters/agent-codex.ts`: full adapter implementations
- `src/adapters/index.ts`: adapter registry entries
- `src/adapters/agent-session.ts`: shared adapter base
- `src/sessions/sweep-state.ts`: `SweepMode` type includes legacy modes
- `src/sessions/sweep.ts`: `agentPrefixes` function
- `src/slots/index.ts`: legacy adapter cases in session fallback (line 172)
- Various test files

**Approach:**
- **Simplify `launchSessionFromNotification`**: Remove the `rawAdapter` parameter entirely. Hardcode `"t3code"`. The legacy regex matchers still capture an adapter group from notification text but it's always normalized away — they can ignore the captured group.
- **Keep `normalizeLaunchAdapter` for now**: The legacy notification regex matchers still need it for backward compatibility (task file notes that legacy regex cleanup was intentionally deferred). Instead, add a deprecation comment.
- **Keep legacy adapter files**: `agent-claude.ts`, `agent-codex.ts`, and the sweep infrastructure should remain until legacy sessions are fully gone (per task notes: "not enough time has passed for legacy notifications to clear").
- **Clean up doctor output**: The `primaryAgent` mapping to `agent-codex`/`agent-claude` adapter names (line 1769-1772) can be simplified to always say `t3code`.

**Files:** `src/mag.ts`, `src/mag.test.ts`
