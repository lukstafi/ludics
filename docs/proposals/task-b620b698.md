# Proposal: Add atomic queue pop commands: ludics mag queue pop one/all

**Task:** task-b620b698
**Date:** 2026-04-03

## Goal

Provide safe manual queue pop commands (`ludics mag queue pop one` and `ludics mag queue pop all`) so operators can drain or inspect queue items without relying on the stop hook, while matching the existing atomicity guarantees.

## Acceptance Criteria

- `ludics mag queue pop one` prints the first queue item as a single JSON line to stdout, removes it from `mag/queue.jsonl`, and exits 0. Exits 1 with no output if the queue is empty.
- `ludics mag queue pop all` prints all queue items as JSONL (one per line) to stdout, empties `mag/queue.jsonl`, and exits 0. Exits 1 with no output if the queue is empty.
- `ludics mag queue` (no subcommand) continues to show the human-readable summary (backward compatible).
- Both pop commands emit `queue_pop` events for observability.
- Both pop commands handle missing or empty queue file gracefully (exit 1).
- The pop functions live in `src/queue.ts` alongside existing queue utilities, reducing duplication with `dequeueQueueHead` in `src/mag.ts`.
- Help text for `ludics mag` lists the new subcommands.

## Context

Currently, the queue is only consumed by the stop hook (`ludics mag queue-pop`), which calls `dequeueQueueHead()` in `src/mag.ts`. When manual intervention is needed (stuck queue, debugging), there is no CLI command to safely pop items. The existing `queuePop()` in `src/queue.ts` is unused in production and lacks the compare-and-swap guard of `dequeueQueueHead()`.

### Atomicity

Neither the current `dequeueQueueHead` nor `queuePop` uses file locking. Concurrent appends via `appendFileSync` are safe for small writes (< PIPE_BUF). The race window between a pop's read and write is tiny, and manual pop commands are infrequent single-user operations. The new commands will match the existing risk profile — no new locking mechanism is introduced.

### Key files

| File | Relevance |
|------|-----------|
| `src/queue.ts` | Existing queue utilities; new `queuePopOne()` and `queuePopAll()` go here |

## Approach

### 1. Add `queuePopOne()` and `queuePopAll()` to `src/queue.ts`

**`queuePopOne(): string | null`** — Read queue file, take first line, write remaining lines back (write-tmp + rename pattern from `orchestration/util.ts`), emit event, return the line. Return null if empty.

**`queuePopAll(): string[]`** — Read queue file, write empty string via write-tmp + rename, emit event, return all lines. Return empty array if empty.

Both use the write-tmp + rename pattern (`writeFileSync` to `.tmp`, `renameSync` over original) already established in `orchestration/util.ts:39-40`, `sweep-state.ts:140-141`, and `report.ts:110-111`. This is a slight improvement over the current `dequeueQueueHead` which uses plain `writeFileSync` directly to the queue file.

### 2. Extend `case "queue"` in `magMain()` (`src/mag.ts`)

Change the existing handler from unconditionally calling `queueShow()` to dispatching on subcommands:

```
case "queue": {
  const sub = args[1];
  if (sub === "pop") {
    const mode = args[2];  // "one" or "all"
    // call queuePopOne/queuePopAll, print to stdout, set exit code
  } else {
    queueShow();  // backward compatible
  }
  break;
}
```

Exit code: use `process.exitCode = 1` when the queue is empty.

### 3. Update help text

Add `mag queue pop one|all` to the usage output in `magMain()`'s default/help case and in `src/index.ts` if it lists mag subcommands.

### 4. Optional: refactor `dequeueQueueHead` to use shared pop

The stop hook's `dequeueQueueHead` could be refactored to call the new `queuePopOne()` internally. However, since `dequeueQueueHead` has the `expectedLine` compare-and-swap parameter used by `drainProgrammaticQueueHead`, this refactoring is not required for this task. It can be done as a follow-up to reduce duplication without risking the stop hook path.
