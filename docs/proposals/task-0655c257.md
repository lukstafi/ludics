# Dashboard: adapter label as toggle button (tmux/t3code <-> manual)

## Goal

Make the adapter mode label on the dashboard a fully functional toggle button that works during active sessions and supports all adapter types (tmux, t3code, manual). Currently, the toggle hardcodes `tmux` as the fallback when switching from manual, and there is no `.mode-tmux` CSS styling. Fix the frontend to use the global default adapter from config when toggling from manual, and add the missing tmux button style.

## Acceptance Criteria

1. When a slot's mode is `manual`, clicking the toggle switches it to the global default adapter (from `adapter.json`, not hardcoded `tmux`). When the mode is `tmux` or `t3code`, clicking switches to `manual`.
2. The dashboard JS fetches `adapter.json` on each refresh cycle and uses its `adapter` field to determine the "other mode" when the current mode is `manual`.
3. The toggle button renders for all non-empty slots that have a mode, regardless of whether a session is active (the backend `slotSetMode` already handles graceful teardown for automated-to-manual transitions during active sessions).
4. A `.mode-toggle-btn.mode-tmux` CSS rule exists, styled consistently with the existing `.mode-t3code` and `.mode-manual` rules (using a distinct color variable).
5. The backend `/api/slot-mode` endpoint already accepts `manual`, `tmux`, and `t3code` -- no backend changes needed.
6. The backend `slotSetMode()` already handles active-session teardown (automated->manual) and rejection (manual->automated with active session) -- no backend changes needed.
7. All existing tests pass.

- Already handles: automated->manual with active session (calls `slotStop` then updates mode), rejects manual->automated with active session. No changes needed.

## Approach

*Suggested approach -- agents may deviate if they find a better path.*

### A. Fetch and store global adapter in dashboard.js

Add a `fetchAdapter()` function that fetches `adapter.json` and stores `window.__globalAdapter` (defaulting to `"tmux"`). Add it to the `fetchAllData()` Promise.all array.

```js
async function fetchAdapter() {
    try {
        const response = await fetch(CONFIG.dataPath + 'adapter.json');
        if (!response.ok) return;
        const data = await response.json();
        window.__globalAdapter = data.adapter || 'tmux';
    } catch {
        // adapter.json may not exist; default handled at usage site
    }
}
```

### B. Use global adapter in toggle rendering (line 155)

Replace the hardcoded `'tmux'`:

```js
const otherMode = slot.mode === 'manual'
    ? (window.__globalAdapter || 'tmux')
    : 'manual';
```

### C. Add `.mode-tmux` CSS rule (style.css, after `.mode-t3code`)

```css
.mode-toggle-btn.mode-tmux {
    border-color: var(--info, #17a2b8);
    color: var(--info, #17a2b8);
}
```

Use `--info` (or a similar distinct color) so tmux buttons are visually distinguishable from t3code (green) and manual (yellow/warning).

### D. No backend changes

The backend already supports all three modes in the API endpoint and handles active-session teardown correctly. No changes to `dashboard-server.ts` or `slots/index.ts`.

### E. No new tests required

The toggle UI is exercised through the existing `slotSetMode` tests. The frontend change is a simple variable lookup. If desired, a manual verification: set `adapter: tmux` in config, load dashboard with a manual-mode slot, confirm the toggle button targets `tmux`; then change config to `adapter: t3code` and confirm it targets `t3code`.
