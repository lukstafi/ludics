# Gate pr-create to pr-comments transition on prUrl being set

## Goal

Prevent the orchestrator from advancing past `pr-create` when no PR actually exists. Currently, `evaluateTransition()` unconditionally returns `"pr-comments"` when agents are done or timeout expires, regardless of whether a PR URL was set. The existing `verifyPrCreateOutcome()` gate in the runner can be bypassed (stale build, code path bugs) and its retry mechanism has two defects: redispatches burn through instantly (no timer reset) and the terminal "hold" state loops silently forever.

Fix all layers: add defense-in-depth prUrl guard in `evaluateTransition`, fix the redispatch timer, add pr-create/update-docs to timeout interrupts, and make the hold state visible.

Ref: Retrospective from task-f3b6e620 (slot 5 advanced to pr-comments with prUrl=null)

## Acceptance Criteria

1. `evaluateTransition()` for `pr-create` returns `null` (no transition) when `!hasAnyPr(state)`, even if agents are done or timeout expired. The `"pr-comments"` transition only fires when at least one agent has a valid prUrl.
2. `preparePhaseRedispatch()` resets `state.phaseStartedAt` to `nowEpoch()` so that retried phases get a fresh timeout window instead of immediately re-expiring.
3. `handleTimeout()` interrupts agents in `pr-create` and `update-docs` phases (added to the interrupt list alongside work/review/pr-comments/final-merge/forward-pr).
4. After `MAX_VERIFY_ATTEMPTS` exhausted, the hold path sets `state.phase` to `"setup-failed"` (or equivalent terminal state) so the slot stops looping and is visible as blocked in the dashboard -- not silently spinning.
5. Existing tests pass; new tests cover: (a) `evaluateTransition` returns `null` for pr-create when no prUrl, (b) `preparePhaseRedispatch` resets `phaseStartedAt`.

## Context

**Phase transition** (`src/orchestration/phases.ts`):
- Lines 440-444: `evaluateTransition` pr-create case -- unconditionally returns `"pr-comments"` on done/timeout. This is where the `hasAnyPr(state)` guard must be added.
- Lines 302-304: `hasAnyPr()` -- checks `runtime.prUrl` across all agents. Already used in the `update-docs` case (line 436) but not in `pr-create`.

**Verification gate** (`src/orchestration/runner.ts`):
- Lines 48-71: `verifyPrCreateOutcome()` -- returns advance/redispatch/hold/skip. Correctly blocks when prUrl is null, but redispatch+hold have defects.
- Lines 109-154: `handleVerifyFailure()` -- retry counter, emits events, calls `preparePhaseRedispatch()` or returns "hold". At max attempts, emits `manual_intervention_required` event but does not change state.phase.
- Lines 174-187: `preparePhaseRedispatch()` -- resets agent statuses and `phaseDispatched` but does NOT reset `phaseStartedAt`, causing instant re-timeout on retry.

**Main loop** (`src/orchestration/runner.ts`):
- Lines 1196-1204: Gate decision check -- on `hold`, the loop does `continue` (infinite silent spin). After fix, hold should transition to a terminal/error state instead.

**Timeout handling** (`src/orchestration/runner.ts`):
- Lines 833-863: `handleTimeout()` -- interrupt list includes work, review, pr-comments, final-merge, forward-pr. Missing: pr-create, update-docs. Early-return list (lines 834-841) covers clarify, pushback, plan, plan-merge, plan-review.

## Approach

*Suggested approach -- agents may deviate if they find a better path.*

1. **`phases.ts` line 443**: Add `hasAnyPr(state)` guard:
   ```typescript
   case "pr-create":
     if (!(allAgentsDone(state) || phaseTimeoutExpired(state))) return null;
     if (!hasAnyPr(state)) return null;
     return "pr-comments";
   ```

2. **`runner.ts` `preparePhaseRedispatch()`** (line ~186): Add `state.phaseStartedAt = nowEpoch();` so retries get a fresh timeout window.

3. **`runner.ts` `handleTimeout()`** (line ~850): Add `"pr-create"` and `"update-docs"` to the interrupt condition:
   ```typescript
   if (
     state.phase === "work"
     || state.phase === "review"
     || state.phase === "pr-create"
     || state.phase === "update-docs"
     || state.phase === "pr-comments"
     || state.phase === "final-merge"
     || state.phase === "forward-pr"
   ) {
   ```

4. **`runner.ts` hold path** (line ~1200): When `gateDecision === "hold"`, instead of `continue`, transition to a terminal state (e.g., set `state.phase = "setup-failed"`) and break, or set a flag that the dashboard renders as blocked.

5. **Tests** (`src/orchestration/phases.test.ts`): Add test for pr-create transition returning `null` when no agent has prUrl set. Add test in runner tests for `preparePhaseRedispatch` resetting `phaseStartedAt`.
