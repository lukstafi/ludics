# Gate pr-create to pr-comments transition on prUrl

## Goal

Fix a bug where the orchestration engine advances from `pr-create` to `pr-comments` even when no PR was actually created. This was observed on 2026-04-03 when a slot advanced with `prUrl=null`, causing the `pr-comments` phase to monitor a nonexistent PR indefinitely.

The root cause is multi-layered: `evaluateTransition()` has no prUrl guard, redispatch retries burn through instantly because `phaseStartedAt` is not reset, the hold state loops silently with no visible error, and `handleTimeout()` does not interrupt agents in `pr-create` or `update-docs` phases.

## Acceptance Criteria

- `evaluateTransition()` must not return `"pr-comments"` from `pr-create` unless at least one agent has a valid prUrl set (defense-in-depth guard independent of the runner verification gate)
- `preparePhaseRedispatch()` must reset `phaseStartedAt` so retried agents get a fresh timeout window instead of immediately timing out again
- `handleTimeout()` must interrupt agents in `pr-create` and `update-docs` phases when their timeout expires, consistent with other active phases
- After `MAX_VERIFY_ATTEMPTS` exhausted, the slot must enter a visibly blocked state (not silently loop in hold)
- Auto-commit uncommitted worktree changes when agents complete `work` or `update-docs` phases (before phase boundary, not just at phase boundary)

## Context

Key files and code pointers:

- **`src/orchestration/phases.ts:440-444`** -- `evaluateTransition()` pr-create case. Currently returns `"pr-comments"` unconditionally when agents are done or timeout expires. The `hasAnyPr(state)` helper (line 302-304) already exists and is used in the `update-docs` case (line 436) but not here.

- **`src/orchestration/runner.ts:48-71`** -- `verifyPrCreateOutcome()` gate. Runs in the main loop (line 1196) between `pollUntilDone` and `evaluateTransition`. Returns `"redispatch"` or `"hold"` when prUrl is missing. This is the first line of defense but can be bypassed if the build is stale.

- **`src/orchestration/runner.ts:174-187`** -- `preparePhaseRedispatch()`. Resets agent status and `phaseDispatched` but does NOT reset `state.phaseStartedAt`. This means on the next loop iteration, `phaseTimeoutExpired()` immediately returns true, burning through all retry attempts in seconds.

- **`src/orchestration/runner.ts:109-154`** -- `handleVerifyFailure()`. After `MAX_VERIFY_ATTEMPTS`, returns `"hold"` which causes the main loop to `continue` indefinitely. Emits a `manual_intervention_required` event and notification but does not change the phase or set any state flag that the dashboard could display as a blocked/error state.

- **`src/orchestration/runner.ts:833-863`** -- `handleTimeout()`. Interrupts agents in `work`, `review`, `pr-comments`, `final-merge`, and `forward-pr` phases. Does NOT include `pr-create` or `update-docs`, so agents in those phases continue running after timeout with no interruption.

- **`src/orchestration/runner.ts:931+`** -- `autoCommitAllAgents()` / `autoCommitAgent()`. Currently called at line 1193 after `pollUntilDone` with `push=false`, and at line 1224 before PR-related phases with `push=true`.

## Approach

*Suggested approach -- agents may deviate if they find a better path.*

1. **phases.ts line 443**: Add `if (!hasAnyPr(state)) return null;` before returning `"pr-comments"`, mirroring the guard already used in the `update-docs` case at line 436.

2. **runner.ts `preparePhaseRedispatch()`**: Add `state.phaseStartedAt = nowEpoch();` to give retried agents a fresh timeout window.

3. **runner.ts `handleTimeout()`**: Add `"pr-create"` and `"update-docs"` to the phase list at lines 850-856 that triggers agent interruption.

4. **runner.ts `handleVerifyFailure()`**: After max attempts, set a state flag (e.g. `state.blocked = true` or transition phase to an error marker) so the dashboard and slot display show the slot is stuck, rather than silently looping.

5. **runner.ts main loop or `pollUntilDone`**: Trigger `autoCommitAllAgents` when `allAgentsDone` first becomes true inside `pollUntilDone`, capturing uncommitted work before phase transition logic runs.
