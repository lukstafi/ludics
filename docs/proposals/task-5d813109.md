# Proposal: Add freshness gate to isAgentDone settled branch and fix skipToPhase lifecycle cleanup

**Task**: task-5d813109
**Project**: ludics

## Goal

Close two defensive gaps in the orchestration lifecycle:

1. The `isAgentDone()` settled branch trusts done-status without verifying the status file was written after the most recent dispatch (unlike the null-lifecycle branch which has a fingerprint freshness gate).
2. `skipToPhase()` does not reset agent `turnLifecycle` or `status` fields, leaving stale lifecycle state that can interact with gap (1) to produce false done signals.

## Acceptance Criteria

1. **Fingerprint freshness gate in settled branch** (`src/orchestration/phases.ts`, `isAgentDone()` settled case, currently line 266):
   - Before calling `validateDoneStatus()`, compare `runtime.dispatchStatusFingerprint` against the current `statusFileFingerprint(state.peerSyncDir, agent.name)`.
   - If the fingerprint is non-null and unchanged since dispatch, emit an `orchestration_warning` event and return `false` (stale status).
   - This mirrors the identical gate in the null-lifecycle branch (lines 240-254).

2. **Extract shared freshness-check helper** (optional but recommended):
   - Factor the fingerprint comparison + warning emit into a private helper (e.g. `isStatusFresh(state, agent, runtime): boolean`) to eliminate duplication between the null-lifecycle branch (lines 240-254) and the new settled-branch gate.
   - Both branches call the helper; behavior is identical to the current null-lifecycle gate.

3. **Agent reset loop in `skipToPhase()`** (`src/orchestration/runner.ts`, currently lines 1446-1458):
   - After setting `state.phase`, `state.phaseStartedAt`, and `state.phaseDispatched = false`, iterate all agents and reset:
     - `runtime.status = "idle"`
     - `runtime.statusEpoch = nowEpoch()`
     - `runtime.statusMessage = \`skip to ${phase}\``
     - `runtime.turnLifecycle = null`
   - This matches the reset loop in `enterPhase()` (lines 1287-1294).

4. **Unit tests** (in existing test files):
   - `phases.test.ts`: settled branch with stale fingerprint (fingerprint === baseline) returns `false`.
   - `phases.test.ts`: settled branch with fresh fingerprint (fingerprint differs) returns `true` (existing behavior preserved).
   - `runner.test.ts`: `skipToPhase()` clears `turnLifecycle` and resets `status` to `"idle"` for all agents.

5. **All existing tests pass** unchanged.

### Combined failure path

`skipToPhase()` leaves stale `turnLifecycle` with `state: "settled"` from a previous phase. The next dispatch loop enters `isAgentDone()` settled branch, which currently calls `validateDoneStatus()` without checking fingerprint freshness. If the old status happens to be in `DONE_STATUSES` and the artifact from the previous phase still exists on disk, the agent is falsely reported as done in the new phase.

### Approach

Both fixes are small, localized, and have clear precedent in adjacent code. The fingerprint gate is a copy of the existing null-lifecycle gate (or better, extracted into a shared helper). The `skipToPhase` reset is a copy of the `enterPhase` reset loop. No architectural decisions needed.
