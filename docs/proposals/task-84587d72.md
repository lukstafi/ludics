# Proposal: Convert handleTimeout to deny-list and unify verification gate pattern

## Goal

Reduce maintenance burden and prevent future bugs in `src/orchestration/runner.ts` by:
1. Converting `handleTimeout` from an opt-in allowlist to a deny-list, so new phases automatically inherit timeout/interrupt behavior.
2. Extracting a unified `verifyPhaseOutcome` helper from `verifyPrCreateOutcome` and `verifyFinalMergeOutcome` to eliminate ~60 lines of duplicated logic.

## Acceptance Criteria

- `handleTimeout` uses `PHASE_CATEGORIES` to decide which phases to skip (deny-list), not an explicit list of phases to include (allowlist). Phases in category `"pre-work"` and `"terminal"` are skipped; all others trigger agent interrupts.
- Adding a new phase to `phases.ts` does NOT require updating `handleTimeout` (unless the phase belongs to a new category that should be excluded).
- A single `verifyPhaseOutcome(state, config)` function replaces both `verifyPrCreateOutcome` and `verifyFinalMergeOutcome`.
- Two gate config constants (`PR_CREATE_GATE`, `FINAL_MERGE_GATE`) capture the per-phase differences (phase name, gate key, success condition, event type, message formatting).
- Call sites at line ~1215-1216 are updated to use the unified function.
- `handleVerifyFailure` remains unchanged.
- All existing orchestration tests pass without modification (behavior is preserved).

### Current behavior

**handleTimeout:** Two blocks -- a guard returns early for `clarify | pushback | plan | plan-merge | plan-review`, then an allowlist interrupts agents for `work | review | update-docs | pr-create | pr-comments | final-merge | forward-pr`. Phases like `merge-vote`, `merge-debate`, `merge-execute`, `merge-review`, `merge-amend`, and `suggest-refactor` are NOT covered -- an omission the deny-list approach fixes.

**Verification gates:** Both functions follow the same 6-step pattern: (1) phase guard, (2) all-done/timeout guard, (3) `getFirstPrUrl` with failure fallback, (4) `getPrVerification`, (5) success check + event + cleanup, (6) failure detail + `handleVerifyFailure`. Differences are: phase name, gate key, success predicate (`v.exists` vs `v.exists && v.merged`), event type, and failure message formatting.

## Approach

### Part 1: handleTimeout deny-list

Replace both blocks in `handleTimeout` (lines 834-867) with:

```ts
async function handleTimeout(state: OrchestrationState, transport: OrchestrationTransport): Promise<void> {
  const category = PHASE_CATEGORIES[state.phase];
  if (category === "pre-work" || category === "terminal") return;

  // Note: for forwarded pr-comments (upstream monitoring), timeout interrupts are NOT
  // suppressed. [existing comment preserved]

  for (const agent of state.agents) {
    if (!agentParticipatesInPhase(state, agent)) continue;
    const runtime = state.agentStates[agent.name]!;
    if (runtime.interrupted || runtime.status === "done" || runtime.status === "review-done") continue;
    await interruptAgent(state, agent, transport);
  }
}
```

Import `PHASE_CATEGORIES` from `./phases.ts` (already imported via `phases.ts` barrel -- verify).

### Part 2: Unified verification gate

Define a `VerificationGateConfig` interface and two constants, then a single `verifyPhaseOutcome`:

```ts
interface VerificationGateConfig {
  phase: Phase;
  gate: "prCreate" | "finalMerge";
  successEvent: string;
  checkSuccess: (v: PrVerification) => boolean;
  formatSuccess: (prUrl: string, v: PrVerification) => string;
  formatFailure: (prUrl: string, v: PrVerification) => string;
}

const PR_CREATE_GATE: VerificationGateConfig = {
  phase: "pr-create",
  gate: "prCreate",
  successEvent: "pr_verified",
  checkSuccess: (v) => v.exists,
  formatSuccess: (prUrl, v) => `PR verified (${v.state}): ${prUrl}`,
  formatFailure: (prUrl, v) => `${v.reason}: ${prUrl}`,
};

const FINAL_MERGE_GATE: VerificationGateConfig = {
  phase: "final-merge",
  gate: "finalMerge",
  successEvent: "merge_verified",
  checkSuccess: (v) => v.exists && v.merged,
  formatSuccess: (prUrl) => `PR merge verified: ${prUrl}`,
  formatFailure: (prUrl, v) => {
    let detail = v.reason;
    if (v.exists && !v.merged) {
      detail = `PR is ${v.state} but not merged`;
      if (v.mergeableState && v.mergeableState !== "clean") {
        detail += ` (mergeable_state: ${v.mergeableState})`;
      }
    }
    return `${detail}: ${prUrl}`;
  },
};

function verifyPhaseOutcome(state: OrchestrationState, config: VerificationGateConfig): VerificationDecision {
  if (state.phase !== config.phase) return "skip";
  if (!(allAgentsDone(state) || phaseTimeoutExpired(state))) return "skip";

  const prUrl = getFirstPrUrl(state);
  if (!prUrl) {
    return handleVerifyFailure(state, config.gate, "No PR URL found" + (config.gate === "prCreate" ? " in agent state or .pr artifact" : ""));
  }

  const v = getPrVerification(prUrl);
  if (config.checkSuccess(v)) {
    emitEvent({
      event_type: config.successEvent,
      source: "orchestration", scope: "slot",
      slot: state.slot, task: state.taskId,
      action: `${config.phase} verification`, status: "success",
      message: config.formatSuccess(prUrl, v),
    });
    state.phaseRetryContext = null;
    return "advance";
  }

  return handleVerifyFailure(state, config.gate, config.formatFailure(prUrl, v));
}
```

Call sites become:
```ts
const prCreateDecision = verifyPhaseOutcome(state, PR_CREATE_GATE);
const finalMergeDecision = verifyPhaseOutcome(state, FINAL_MERGE_GATE);
```
