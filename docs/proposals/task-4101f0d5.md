# Proposal: Add argv root override + spawnSync CLI exit-code tests to all `scripts/lint-*.ts`

**Task:** task-4101f0d5
**Project:** ludics
**Effort:** small (scope-extended; expect medium)

## Goal

Bring every `scripts/lint-*.ts` script up to the convention established by
`lint-template-safety.ts` and `lint-vendor-sync.ts` (PR #446): the
`import.meta.main` block reads `process.argv[2]` as a root/dir override, and
the companion `*.test.ts` drives the *real* CLI via `spawnSync` to assert the
process exit code in both the success and failure cases.

The motivating durable learning (from task-d024e32c retrospective): pure-helper
unit tests do not catch CLI mis-wiring — `console.log` instead of
`console.error`, missing `process.exit`, an early `return`, or `process.exit(0)`
where it should be `process.exit(1)` all sail through helper coverage. The
class of regression a lint exists to prevent in the codebase it audits should
not be silent in the lint script itself.

The scope-extension answers (Q1–Q4 in the task file) bring four scripts into
this PR plus a fifth deliverable: rewriting `lint:no-mock-module` from a
`grep` one-liner in `package.json` into a real `scripts/lint-no-mock-module.ts`
with the same convention.

## Acceptance Criteria

### Per-script falsifier ACs

For each of the **five** scripts below, the following three ACs must hold.
Each AC names its mutation falsifier — the kind of regression it catches:

1. `scripts/lint-cli-readme.ts`
2. `scripts/lint-config-reference.ts`
3. `scripts/lint-contracts.ts`
4. `scripts/lint-test-isolation.ts`
5. `scripts/lint-no-mock-module.ts` *(new file)*

- [ ] **Negative-branch exit-code test.** A `spawnSync`-driven test in the
      script's `.test.ts` companion asserts `result.exitCode !== 0` (or
      `=== 1`) against a tmp fixture instantiating the failure case for that
      lint. *Mutation falsifier:* replacing the script's `process.exit(1)`
      with `process.exit(0)`, removing the call, or returning early before
      the exit must cause this test to fail.

- [ ] **Happy-path exit-code test.** A `spawnSync`-driven test in the same
      file asserts `result.exitCode === 0` against a tmp fixture instantiating
      the success case. *Mutation falsifier:* hard-coding `process.exit(1)`
      unconditionally, or moving the `console.log("✅ …")` happy-path branch
      after a stray `process.exit(1)` must cause this test to fail.
      (Both directions per the `lint-vendor-sync.test.ts` precedent —
      Q4 worker decision.)

- [ ] **`import.meta.main` accepts `process.argv[2]` as a root/dir override.**
      When present, the override replaces the hard-coded `join(import.meta.dir, "..")`
      (or equivalent) so the spawned CLI reads the tmp fixture instead of the
      real repo. *Mutation falsifier:* removing the argv read collapses the
      override back to the real repo, the tmp fixture is ignored, and the
      spawnSync tests above either become flaky against repo state or stop
      exercising their fixtures.

### Aggregate ACs

- [ ] **`lint:no-mock-module` rewrite.** `package.json`'s `"lint:no-mock-module"`
      script invokes `bun run scripts/lint-no-mock-module.ts` (not the
      `! grep -r 'mock\.module(' …` one-liner). The new script ports the same
      semantics: scan `src/` and `templates/` for `*.test.ts` files containing
      `mock.module(`, print offending paths to stderr, and exit non-zero if
      any are found. *Mutation falsifier:* reverting to the grep one-liner
      leaves no test file for the script and makes `bun run lint:no-mock-module`
      not dispatch to the new TS module.

- [ ] **Tmp-fixture cleanup hygiene.** Every new spawnSync test uses
      `mkdtempSync(join(tmpdir(), "<prefix>-"))` (or the existing
      `makeFixture`-style helper in the file) followed by a
      `try { … } finally { rmSync(dir, { recursive: true, force: true }); }`
      pattern, matching the `lint-vendor-sync.test.ts` and durable-learning
      convention from task-c2af46fa. *Mutation falsifier:* a leaked tmp dir
      shows up in `git status` checks or breaks the existing test cleanup
      convention enforced by other lint tests.

- [ ] **`scripts/lint-config-reference.test.ts` exists** (created from
      scratch — no test file exists today). It contains at minimum: a
      happy-path tmp fixture (all three files in sync, exits 0) and a drift
      tmp fixture (e.g., a key in `config.reference.yaml` not in `src/config.ts`,
      exits 1). The script is refactored to expose `runLint(root)` so
      `import.meta.main` becomes a thin
      `process.exit(runLint(process.argv[2] ?? defaultRoot).exitCode)` wrapper
      that preserves the existing `tsPaths.delete("staleThresholdSeconds")`
      env-var carve-out and the `LUDICS_HARNESS_CONFIG_PATH` env override.

- [ ] **All lint tests pass.** `bun test scripts/lint-*.test.ts` passes,
      including the five new test additions. *Mutation falsifier:* removing
      any of the new tests drops coverage and lets the lint regression class
      become silent again.

## Approach

The work is naturally five parallel chunks. Each can be a separate commit
with `[round N]` prefix; the orchestrator's plan phase will decide
sequencing.

### 1. `lint-cli-readme.ts`

- Add `process.argv[2]` override to the `import.meta.main` block. The current
  block uses a module-scoped `root = join(import.meta.dir, "..")`; introduce
  `const argRoot = process.argv[2]; const cliRoot = argRoot ? argRoot : root;`
  and read `src/index.ts` + `README.md` from `cliRoot`.
- Append two cases to `scripts/lint-cli-readme.test.ts`:
  - **Happy-path:** tmp dir with `src/index.ts` (containing a USAGE block) and
    `README.md` (containing a matching `## CLI Reference`); `spawnSync` →
    `exitCode === 0`.
  - **Negative:** tmp dir with a stale command in `## CLI Reference` not in
    USAGE; `spawnSync` → `exitCode === 1`.
- Use `mkdtempSync(join(tmpdir(), "lint-cli-readme-"))` + try/finally cleanup,
  matching `lint-vendor-sync.test.ts`.

### 2. `lint-config-reference.ts` (largest chunk)

- **Refactor:** Extract the `import.meta.main` body into an exported
  `runLint(root: string): { exitCode: number; … }` helper. The helper reads
  `templates/config.reference.yaml`, `src/config.ts`, and the harness config
  (still honoring `LUDICS_HARNESS_CONFIG_PATH` env override) from the passed
  `root`. Carry the `tsPaths.delete("staleThresholdSeconds")` carve-out and
  the FREEFORM_CHILDREN / WILDCARD_MAP_PATHS sets into the helper.
- `import.meta.main` becomes:
  ```ts
  if (import.meta.main) {
    const argRoot = process.argv[2];
    const root = argRoot ? argRoot : join(import.meta.dir, "..");
    process.exit(runLint(root).exitCode);
  }
  ```
- **Create `scripts/lint-config-reference.test.ts`** (new file). At minimum:
  - **Happy-path fixture:** tmp dir with `templates/config.reference.yaml`,
    `templates/harness/config.yaml`, and `src/config.ts` whose interface keys
    align; `spawnSync` → `exitCode === 0`.
  - **Drift fixture:** tmp dir where `config.reference.yaml` declares a key
    that `src/config.ts` doesn't (or vice-versa); `spawnSync` → `exitCode === 1`.
  - **Optional:** harness-extras fixture (templates/harness has a key not in
    reference) to cover Direction 3.
  - Test files use `mkdtempSync` + try/finally with `rmSync`.

### 3. `lint-contracts.ts`

- Thread `process.argv[2]` into `runCli`'s existing `skillsDir` option:
  ```ts
  if (import.meta.main) {
    process.exit(runCli({ skillsDir: process.argv[2] || undefined }).exitCode);
  }
  ```
  (The `|| undefined` preserves the default-resolution branch in `runCli` when
  no arg is passed.)
- Append a spawnSync negative test to `scripts/lint-contracts.test.ts` that
  reuses the existing `makeFixture` helper at line ~298. Pick a fixture shape
  that genuinely returns `exitCode: 1` — e.g., a worker skill with a missing
  required field, mirroring an existing `driveRunCli` failure case but
  asserting via `spawnSync` instead.
- Add a happy-path spawnSync test using a known-good `makeFixture` shape
  (mirror an existing `expect(exitCode).toBe(0)` `driveRunCli` case).

### 4. `lint-test-isolation.ts`

- Mirror the contracts pattern. Thread `process.argv[2]` into `runCli`'s
  `srcDir` option (and let `repoRoot` default to `dirname(srcDir)` per the
  existing logic at line ~393–394):
  ```ts
  if (import.meta.main) {
    process.exit(runCli({ srcDir: process.argv[2] || undefined }).exitCode);
  }
  ```
- Add spawnSync happy-path + negative tests to
  `scripts/lint-test-isolation.test.ts`. The negative fixture instantiates a
  `*.test.ts` file violating one of the three rules (e.g., a top-level
  `mock.module(…)` call → rule 1, or an offending neighbour-import structure →
  rule 3).

### 5. `lint-no-mock-module` (new TS script + new test)

- **Create `scripts/lint-no-mock-module.ts`.** Port the
  `! grep -r 'mock\.module(' src/ templates/ --include='*.test.ts' -l`
  one-liner. Shape:
  ```ts
  export function runLint(root: string): { exitCode: number; offenders: string[] } {
    // Walk src/ and templates/ under `root`, filter to *.test.ts,
    // collect any whose contents contain `mock.module(`.
  }

  if (import.meta.main) {
    const argRoot = process.argv[2];
    const root = argRoot ? argRoot : join(import.meta.dir, "..");
    const { exitCode, offenders } = runLint(root);
    if (exitCode === 0) {
      console.log("✅  No mock.module(...) usage in *.test.ts files.");
    } else {
      console.error(`\n❌  ${offenders.length} *.test.ts file(s) use mock.module:`);
      for (const f of offenders) console.error(`     - ${f}`);
    }
    process.exit(exitCode);
  }
  ```
- **Update `package.json`:** change line 19 to
  `"lint:no-mock-module": "bun run scripts/lint-no-mock-module.ts"`.
- **Create `scripts/lint-no-mock-module.test.ts`** with:
  - Pure-helper tests for `runLint(root)` against a fixture with no offenders
    (returns `exitCode: 0`) and a fixture with an offender (returns
    `exitCode: 1`, surfaces the path).
  - Two `spawnSync` tests covering both directions, matching the
    `lint-vendor-sync.test.ts` shape: pass the tmp root as argv, assert exit
    code.

### Edge cases and conventions to preserve

- **`spawnSync` import style.** `lint-vendor-sync.test.ts` uses
  `import { spawnSync } from "bun"`. Match the imports already used in each
  test file being extended; don't introduce churn (e.g., don't switch
  `lint-contracts.test.ts` between `Bun.spawnSync` and `import { spawnSync }`).
- **`cwd` for spawnSync.** Set `cwd: join(import.meta.dir, "..")` (repo root)
  so `bun run` resolves the script. The argv override controls *what the
  script reads*, not where it runs.
- **Assertion shape.** Per task-66feb317 Clause 4, assert `exitCode === 1`
  (or `!== 0`) only — *not* stderr contents. Failure-message phrasing is a
  separate concern that would couple this PR to phrasing churn.
- **`lint-config-reference.ts`'s env-var carve-outs.** The
  `tsPaths.delete("staleThresholdSeconds")` line and the
  `LUDICS_HARNESS_CONFIG_PATH` override must move into `runLint(root)`
  unchanged — easy to miss because they're one-liners mid-block.
- **CI cost.** Each new spawnSync test forks a `bun run`. Adding ~10 cases
  total adds maybe 5–15s to CI. Acceptable.
