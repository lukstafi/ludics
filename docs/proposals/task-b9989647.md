# Proposal: CLI commands for t3code thread interaction

## Summary

Add `ludics t3code` subcommands to read agent responses and send messages to t3code threads, enabling Mag and users to interact with orchestrated agents from the CLI.

## Changes

### 1. Thread history reading (`t3code/client.ts`, `t3code/index.ts`)

- Add `getThreadMessages(threadId)` to the WebSocket client — fetches message history from the t3code API
- `ludics t3code thread <id> log [--last N]` — display full message history
- `ludics t3code slot <N> log [--agent coder|reviewer] [--last N]` — convenience wrapper that resolves thread ID from orchestration state
- `ludics t3code slot <N> response [--agent coder|reviewer]` — show only the last assistant message

### 2. Message sending (`t3code/client.ts`, `t3code/index.ts`)

- `ludics t3code thread <id> send "<message>"` — dispatch a `thread.turn.start` command
- `ludics t3code slot <N> send [--agent coder|reviewer] "<message>"` — convenience wrapper
- Reuse existing `sendTurnMessage()` pattern from `runner.ts`

### 3. CLI routing (`t3code/index.ts`)

Add subcommand routing:
```
t3code thread <id> log [--last N]
t3code thread <id> send "<msg>"
t3code slot <N> log [--agent <role>] [--last N]
t3code slot <N> send [--agent <role>] "<msg>"
t3code slot <N> response [--agent <role>]
```
