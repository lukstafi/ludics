# Proposal: Task file renderer and links

## Goal

Add a rendered task file viewer (`task.html`) analogous to the existing `proposal.html` renderer, and update all dashboard/task-tree links so they open rendered HTML instead of raw markdown.

## Acceptance Criteria

- A new `templates/dashboard/task.html` page renders task markdown through `markdownToHtml()`, stripping YAML frontmatter before rendering, and displaying key frontmatter fields (status, priority, project) as badges in the header.
- The Tasks tab tree view links (`node.link` in `generateTasksTree()`) point to `/task.html?task=TASK-ID` instead of `/task-files/TASK-ID.md`.
- The Dashboard tab's Needs Confirmation, Unanswered Questions, and Deferred Launch panels link to `task.html?task=TASK-ID` instead of raw `task-files/TASK-ID.md`.
- The existing `/task-files/` server endpoint is unchanged (the new page fetches from it client-side).
- After `ludics dashboard install`, the new `task.html` is deployed alongside the other template files.

## Context

### Existing renderer pattern

`proposal.html` reads `?task=TASK-ID` from the query string, fetches `/proposal-files/{taskId}.md`, renders the response through `markdownToHtml()` (from `markdown.js`), and displays it inside `<div class="rendered-content">`. The same pattern is used by `retrospective.html` (fetching JSON) and `briefing.html`. All share `style.css`, `content.css`, `markdown.js`, and `nav.js`.

### Server endpoint

`dashboard-server.ts` already serves raw task files at `/task-files/{taskId}.md` (lines 539-558) with `TASK_ID_RE` validation and path-traversal checks. No new endpoint is needed.

### Current raw-file links (4 locations)

1. **`src/dashboard.ts` line 648** -- `generateTasksTree()` sets `taskFileLink = /task-files/${encodeURIComponent(task.id)}.md`.
2. **`templates/dashboard/dashboard.js` line 601** -- `fetchNeedsConfirmation` renders `href="task-files/${escapeHtml(task.id)}.md"`.
3. **`templates/dashboard/dashboard.js` line 622** -- `fetchUnansweredQuestions` renders the same pattern.
4. **`templates/dashboard/dashboard.js` line 638** -- `fetchDeferredLaunch` fallback (when no proposal) uses `task-files/${encodeURIComponent(task.id)}.md`.

## Approach

### 1. Create `templates/dashboard/task.html`

Clone `proposal.html` with these adaptations:

- Title: `ludics Task` / `ludics Task: ${taskId}`.
- Element IDs: `task-task-id`, `task-content` (replacing `proposal-*`).
- Fetch URL: `/task-files/${taskId}.md` instead of `/proposal-files/`.
- Frontmatter stripping: before calling `markdownToHtml()`, remove the `---...---` block with `text.replace(/^---\n[\s\S]*?\n---\n*/, '')`.
- Frontmatter badges: parse the stripped frontmatter to extract `status`, `priority`, and `project`, display them as inline badges in the header area next to the task ID.
- Add a link to the proposal renderer if the frontmatter contains a non-null `proposal` field: `<a href="proposal.html?task=${taskId}">View Proposal</a>`.

### 2. Update `src/dashboard.ts` -- `generateTasksTree()`

Change line 648:
```
const taskFileLink = `/task.html?task=${encodeURIComponent(task.id)}`;
```

This single change updates all task links in the Tasks tab tree because they all read from `node.link`.

### 3. Update `templates/dashboard/dashboard.js` -- 3 link patterns

- **`fetchNeedsConfirmation`** (line 601): `href="task.html?task=${escapeHtml(task.id)}"`.
- **`fetchUnansweredQuestions`** (line 622): same pattern.
- **`fetchDeferredLaunch`** (line 638): change fallback to `task.html?task=${encodeURIComponent(task.id)}`.

### 4. No server-side changes

The `/task-files/` endpoint already exists. The new `task.html` fetches from it client-side, exactly like `proposal.html` fetches from `/proposal-files/`.
