# Proposal: Extract shared markdown.js renderer from duplicated markdownToHtml()

## Summary

Extract the duplicated `markdownToHtml()`, `escapeHtml()`, `inlineFormat()`, and `parseTableRow()` functions into a shared `templates/dashboard/markdown.js` module, then import it from the four files that currently carry their own copies.

## Current state

Four files contain near-identical markdown rendering code:

| File | Functions | Table support | Style |
|------|-----------|---------------|-------|
| `dashboard.js` | all 4 | yes | compact |
| `briefing.html` | all 4 | yes | verbose (comments) |
| `proposal.html` | all 4 | yes | verbose (comments) |
| `retrospective.html` | 3 (no `parseTableRow`) | no | compact |

The `briefing.html` and `proposal.html` copies are byte-for-byte identical (modulo whitespace). The `dashboard.js` copy is functionally identical but formatted more compactly. The `retrospective.html` copy omits table handling entirely.

## Plan

### 1. Create `templates/dashboard/markdown.js`

Export the four functions as globals (no ES modules, matching the project's current script-loading pattern):

```js
// markdown.js -- shared markdown-to-HTML renderer
// Used by: dashboard.js, briefing.html, proposal.html, retrospective.html

function escapeHtml(str) { ... }
function parseTableRow(line) { ... }
function inlineFormat(text) { ... }
function markdownToHtml(md) { ... }
```

Use the most complete version (from `briefing.html` / `proposal.html`) as the canonical implementation, which includes table support. The `retrospective.html` page will gain table rendering for free -- this is harmless since table markup only triggers when pipe-delimited lines are present.

### 2. Update `index.html`

Add `<script src="markdown.js"></script>` before `<script src="dashboard.js"></script>` so the functions are available when `dashboard.js` runs.

### 3. Update `briefing.html`, `proposal.html`, `retrospective.html`

In each file:
- Add `<script src="markdown.js"></script>` before the inline `<script>` block.
- Remove the `markdownToHtml()`, `escapeHtml()`, `inlineFormat()`, and (where present) `parseTableRow()` function definitions from the inline script.

### 4. Remove from `dashboard.js`

Delete the four function definitions (`escapeHtml`, `markdownToHtml`, `parseTableRow`, `inlineFormat`) -- approximately lines 372-475.

## Files to modify

- **New**: `templates/dashboard/markdown.js` -- shared renderer (~105 lines)
- `templates/dashboard/index.html` -- add script tag
- `templates/dashboard/dashboard.js` -- remove ~105 lines
- `templates/dashboard/briefing.html` -- replace ~155 inline lines with 1 script tag
- `templates/dashboard/proposal.html` -- replace ~155 inline lines with 1 script tag
- `templates/dashboard/retrospective.html` -- replace ~65 inline lines with 1 script tag

Net change: ~480 lines removed, ~110 lines added (the new file + 4 script tags).

## Risks

- **None significant.** All implementations are functionally identical. The only behavioral difference is that `retrospective.html` will gain table support, which is additive and harmless.
- No build step or module bundler is involved -- plain `<script>` tags with global functions.

## Verification

- Open each of the four pages in a browser and confirm markdown content renders correctly (headings, lists, bold/italic, code blocks, tables, links).
- Confirm no console errors about undefined functions.
