# Proposal: Extract shared paginatedGhApiCount helper and add per_page=100

**Task**: task-10d50e59
**File**: `src/orchestration/github.ts`

## Goal

Eliminate duplicated paginated GitHub API count logic by extracting a single `paginatedGhApiCount` helper, and add `per_page=100` to reduce unnecessary pagination round-trips (GitHub defaults to 30 items/page).

## Acceptance Criteria

1. A module-level `paginatedGhApiCount(endpoint: string, jqFilter: string): number` function exists in `src/orchestration/github.ts` that:
   - Runs `gh api --paginate <endpoint> --jq <jqFilter>` via `Bun.spawnSync`
   - Sums the per-page integers from stdout
   - Returns 0 on any error (non-zero exit code or exception)
   - Appends `per_page=100` to the endpoint (`?per_page=100` or `&per_page=100` depending on whether `?` is already present)

2. `countViaGhApi()` (the nested function inside `fetchNewPrCommentCount`) is removed; its three call sites delegate to `paginatedGhApiCount` instead.

3. `hasCodexSubmittedReview()` uses `paginatedGhApiCount(...) > 0` instead of inline `Bun.spawnSync` + sum logic.

4. `isPrMerged()` is unchanged (it does not paginate).

5. All existing behavior is preserved -- same return values, same error handling semantics (return 0 / false on failure).

6. Project builds cleanly (`bun run build`).

## Context

- **Source**: retrospective of task-983a1079 identified the duplication and missing `per_page`.
- **Duplication sites**: lines 22-36 (`countViaGhApi` nested function) and lines 85-97 (inline in `hasCodexSubmittedReview`). Both share identical `Bun.spawnSync` invocation, stdout splitting, integer summing, and error handling.
- **per_page gap**: None of the four paginated calls specify `per_page`, so GitHub defaults to 30 items/page, causing extra HTTP round-trips on PRs with many comments/reviews.
- **Scope**: single file, purely mechanical refactor + parameter addition. No new dependencies, no API changes to exported functions.
