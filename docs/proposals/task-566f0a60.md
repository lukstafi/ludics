# Proposal: Extract validateSignal and improve federation-http signal test coverage

**Task**: task-566f0a60
**Date**: 2026-04-06

## Goal

Extract a pure `validateSignal` function from `handleSignal()` in `src/federation-http.ts` and add test coverage for signal validation and dispatch paths (done/error).

## Context

The original task referenced `src/worker-signal.ts`, which was deleted in commit `29cc48b` (PR #196, federation v2). The signal validation and dispatch logic now lives in `handleSignal()` inside `src/federation-http.ts` (lines 394–473). The situation is the same as described in the retrospective: validation logic (taskId match, machine match, epoch TTL check) is mixed with I/O (reading slots file, calling `slotClear`, calling `emitEvent`, calling `clearIntent`). No tests exist for this handler.

**Key source locations:**
- `src/federation-http.ts` — `handleSignal()` at line 394; `SIGNAL_MAX_AGE_SECONDS` constant at line 316; imports `slotClear` from `./slots/index.ts` and `emitEvent` from `./events.ts`
- `src/slots/index.ts` — `slotClear(slotNum, finalStatus)` at line 267; has side effects (file I/O, git, orchestration cleanup)
- `src/orchestration/runner.test.ts` — shows `spyOn(events, "emitEvent").mockImplementation(() => {})` pattern used for mocking `emitEvent`
- `src/federation.test.ts` — pattern for simple federation tests without mocks

## Acceptance Criteria

- `validateSignal` is exported from `src/federation-http.ts` as a pure function with signature:
  ```typescript
  export function validateSignal(
    signal: { taskId: string; machine: string; epoch: number },
    slotTaskId: string,
    slotMachine: string,
    nowEpoch?: number,
  ): { valid: true } | { valid: false; reason: string; httpStatus: number }
  ```
- `handleSignal()` calls `validateSignal()` internally and returns the appropriate HTTP error response when invalid
- Tests in a new `src/federation-http.test.ts` file cover:
  - `validateSignal` pure function: taskId mismatch, missing machine, machine mismatch, expired TTL, valid signal — all without filesystem access
  - `handleSignal` via `handleFederationRequest` dispatch: "done" path verifies `slotClear` is called with correct args (mocked via `spyOn`); "error" path verifies `emitEvent` is called with `event_type: "worker_signal_error"` (mocked via `spyOn`)
  - "progress" status returns 200 without calling `slotClear`
- All existing tests continue to pass

## Approach

### Step 1: Extract `validateSignal` from `handleSignal`

In `src/federation-http.ts`, extract the four validation checks currently in `handleSignal()` into an exported pure function. The function receives the signal fields (`taskId`, `machine`, `epoch`) plus the current slot's `taskId` and `machine` from the slots file, plus an optional `nowEpoch` parameter (defaults to `Math.floor(Date.now() / 1000)`) for deterministic TTL testing.

Return type uses a discriminated union: `{ valid: true }` or `{ valid: false; reason: string; httpStatus: number }` so `handleSignal` can return the correct HTTP response without branching.

`handleSignal()` is refactored to:
1. Parse and validate required fields (400 on missing)
2. Read the slots file (409 if not found)
3. Look up slot block (409 if slot not found)
4. Call `validateSignal(...)` → return 409 with reason on failure
5. Clear intent and dispatch on status as before

### Step 2: Add `src/federation-http.test.ts`

Tests use `bun:test` (describe/test/expect/spyOn/beforeEach/afterEach). Two describe blocks:

**`validateSignal` unit tests** — pure function, no mocking needed:
- taskId mismatch → `{ valid: false, reason: "stale-task" }`
- empty machine → `{ valid: false, reason: "missing-machine" }`
- machine mismatch → `{ valid: false, reason: "machine-mismatch" }`
- expired epoch (age > 1800s) → `{ valid: false, reason: "expired" }`
- epoch = 0 skips TTL check → `{ valid: true }`
- all fields match → `{ valid: true }`

**`handleSignal` integration tests** — use `mkdtempSync` for a temp harness dir, write a minimal `slots.md` fixture, set `process.env.LUDICS_HARNESS_DIR`, spy on `slotClear` and `emitEvent`:
- "done" status → `slotClear` called with `(slot, "done")`, response 200
- "error" status → `emitEvent` called with `event_type: "worker_signal_error"`, response 200
- "progress" status → neither `slotClear` nor `emitEvent` called, response 200
- missing machine field → response 400
- taskId mismatch → response 409
- expired signal → response 409

No other files need changes. The `WorkerSignal` type (if needed) stays local to `federation-http.ts` or is inlined as a structural type in `validateSignal`'s parameter.
