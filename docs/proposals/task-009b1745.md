# Proposal: Fix selectMachineForSlot preference logic

## Goal

Fix `selectMachineForSlot()` so that `always_on` is the primary machine selection signal, with "not the current machine" as only a weak tiebreaker among equally-qualified machines.

Currently, the function excludes the current machine (`m.name !== current`) from the `always_on` pool. When the controller (mac-studio) is the only `always_on` machine and is also the current machine, the `always_on` filter returns empty. The function falls through to "any online non-current machine" and picks the non-always-on laptop (macbook-pro), defeating the purpose of the `always_on` flag.

## Acceptance Criteria

- [ ] When the only `always_on` machine is the current machine, `selectMachineForSlot` returns the current machine (not a non-always-on machine)
- [ ] When multiple `always_on` machines are online, non-current ones are preferred (load balancing tiebreaker)
- [ ] When no `always_on` machines are online, behavior falls back to any online machine (preferring non-current)
- [ ] When only the current machine is online, it is returned

## Context

- **File**: `src/federation.ts`, lines 532-557
- **Function**: `selectMachineForSlot()`
- **Current logic** (3-tier):
  1. `always_on` workers excluding current machine -> picks first
  2. Any online machine excluding current -> picks first
  3. Current machine (last resort)
- **Bug**: Tier 1 excludes current machine, so when current is the only `always_on`, it falls to tier 2 which picks a non-always-on machine

## Approach

Replace the current 3-tier logic with a scoring approach:

```typescript
// Prefer always-on machines; among equals, weakly prefer non-current for load balance
const sorted = [...onlineMachines].sort((a, b) => {
  const aOn = a.always_on ? 1 : 0;
  const bOn = b.always_on ? 1 : 0;
  if (bOn !== aOn) return bOn - aOn; // always_on first
  const aCur = a.name === current ? 1 : 0;
  const bCur = b.name === current ? 1 : 0;
  return aCur - bCur; // non-current preferred as tiebreaker
});
return sorted[0]!.name;
```

This is a ~10-line replacement of the existing ~10-line filter/fallback chain. The sort makes the priority relationship explicit and extensible.
