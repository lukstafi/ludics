# Replace jq-with-fallback in setup.sh trust blocks with bun-only

## Goal

Simplify the two trust blocks in `setup.sh` Step 5 by removing the redundant jq codepaths. Since bun is a hard dependency (installed in Step 1), the jq-primary + bun-fallback pattern is unnecessary complexity. Keep only the bun code, which already handles all edge cases (missing keys, deduplication).

This also renders `task-dda20abf` (JSON validation guards before `mv`) unnecessary, since the jq `.tmp`/`mv` pattern will no longer exist.

## Acceptance Criteria

1. The `PATHS_JSON` variable and its computation (currently line 314: `PATHS_JSON="$(echo "$PATHS_LINES" | jq -R . | jq -s .)"`) are removed.
2. The `if command -v jq` conditional around `PATHS_JSON` (lines 313-315) is removed.
3. The Codex trust block no longer contains an `if command -v jq` branch. Only the bun code remains (current lines 324-333), with the `else`/`fi` wrapper removed.
4. The Claude Code trust block no longer contains an `if command -v jq` branch. Only the bun code remains (current lines 353-363), with the `else`/`fi` wrapper removed.
5. The `PATHS_LINES` variable (line 312) is preserved -- it is used by the bun code to pipe paths via stdin.
6. No `.tmp` file + `mv` pattern remains in Step 5 (that was only in the jq paths).
7. `setup.sh` runs successfully: `bash setup.sh` completes Step 5 without errors when a valid `config.yaml` with project paths is present.
8. After running, `~/.codex/.codex-global-state.json` contains the project paths under `"electron-saved-workspace-roots"` and `~/.claude.json` contains them under `.projects[path].hasTrustDialogAccepted`.
