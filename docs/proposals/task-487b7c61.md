# Proposal: Add lightweight template conditionals

**Task:** task-487b7c61
**Project:** ludics
**Effort:** small

## Goal

Add `{{#IF VAR}}...{{/IF}}` conditional block syntax to `substituteTemplate`, allowing templates to include or exclude sections based on whether a variable is present and non-empty. This eliminates the need for pre-computed "note" variables (like `STAGING_REPO_NOTE`) and enables cleaner template authoring.

## Acceptance Criteria

- `substituteTemplate` supports `{{#IF VAR}}...content...{{/IF}}` syntax
- Block is included when `VAR` is present in the values map AND non-empty
- Block is removed (replaced with empty string) when `VAR` is absent or empty
- Nested `{{VAR}}` placeholders inside conditional blocks are still substituted
- Conditionals can span multiple lines
- Multiple independent `{{#IF}}` blocks work in the same template
- Existing templates and tests continue to pass without modification
- Unit tests cover: truthy var, falsy/missing var, nested substitution, multi-line block, multiple blocks

## Context

### Current code

`substituteTemplate` at `src/orchestration/skills.ts:309-318` is a single-pass regex replacement of `{{VAR}}` placeholders. It warns in dev mode for unknown variables and replaces missing values with empty strings.

### Current workaround

`buildSkillContext` pre-computes variables like `STAGING_REPO_NOTE` that contain formatted text when a condition is true and empty string otherwise. Templates then use `{{STAGING_REPO_NOTE}}` which either renders the note or nothing. This works but forces context-building code to know about template presentation details.

### Key files

- `src/orchestration/skills.ts` -- `substituteTemplate` (line 309)
- `src/orchestration/skills.test.ts` -- existing tests (imports at line 4, tests around lines 97-280)
- `skills/orchestration/*.md` -- template files (no changes needed for this task)

## Approach

**Two-phase replacement** in `substituteTemplate`:

1. **Phase 1 (new):** Process `{{#IF VAR}}...{{/IF}}` blocks with regex `/\{\{#IF\s+([A-Z0-9_]+)\}\}([\s\S]*?)\{\{\/IF\}\}/g`. For each match, keep the body if `values[key]` is present and non-empty, otherwise replace with `""`.

2. **Phase 2 (existing):** Substitute `{{VAR}}` placeholders as today.

This ordering ensures variables inside kept conditional blocks get substituted in phase 2. The `[\s\S]*?` non-greedy match handles multi-line content and multiple independent blocks correctly.

The regex does **not** support nesting (`{{#IF A}}...{{#IF B}}...{{/IF}}...{{/IF}}`). This is intentional -- YAGNI. If needed later, a recursive or iterative approach can be added.

**Test plan:** Add a `describe("substituteTemplate conditionals")` block with tests for:
- Truthy variable includes block content
- Missing variable removes block
- Empty-string variable removes block
- Nested `{{VAR}}` inside conditional gets substituted
- Multi-line conditional block
- Multiple independent `{{#IF}}` blocks in one template
- Dev-mode warning for unknown vars inside conditionals still fires
