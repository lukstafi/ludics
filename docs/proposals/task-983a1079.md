# Audit gh api calls for missing --paginate flag

## Goal

`fetchNewPrCommentCount()` in `src/orchestration/github.ts` silently undercounts
comments/reviews on PRs with >30 items per endpoint because its `countViaGhApi()`
helper omits the `--paginate` flag. This causes the orchestrator to potentially
miss reviewer feedback on high-traffic PRs, skipping the pr-comments phase when
it should re-enter.

## Acceptance Criteria

1. `countViaGhApi()` passes `--paginate` to `gh api` for all three list-endpoint
   calls (review comments, issue comments, reviews).
2. `countViaGhApi()` sums per-page jq output lines instead of parsing a single
   integer, matching the pattern already used in `hasCodexSubmittedReview()`.
3. The `gh api` example in `skills/orchestration/pr-comments.md` includes
   `--paginate`.
4. The `gh api` example in `templates/mag/memory/tools.md` includes `--paginate`.
5. No regressions for single-page results (the `--paginate` flag is a no-op when
   results fit in one page).

## Context

### Key file: `src/orchestration/github.ts`

- **`countViaGhApi()`** (inner function, lines 22-34): currently does
  `parseInt(result.stdout.toString().trim(), 10) || 0` which assumes a single
  integer on stdout. With `--paginate`, `gh api` outputs one jq result per page,
  so multiple lines need summing.

- **`hasCodexSubmittedReview()`** (lines 78-100): already implements the correct
  pattern -- uses `--paginate` (line 85) and sums per-page output (lines 94-95):
  ```typescript
  const total = result.stdout.toString().trim().split("\n")
    .reduce((sum, line) => sum + (parseInt(line, 10) || 0), 0);
  ```

- **Three call sites** in `fetchNewPrCommentCount()` (lines 36-50) pass args to
  `countViaGhApi()` without `"--paginate"` in the array.

### Secondary files

- `skills/orchestration/pr-comments.md` line 8: `gh api` call missing `--paginate`
- `templates/mag/memory/tools.md` line 80: `gh api` example missing `--paginate`

### Caller

`fetchNewPrCommentCount` is called from `checkAndRedispatchPrComments()` in
`src/orchestration/runner.ts` to decide whether to re-enter the pr-comments phase.

## Approach

*Suggested approach -- agents may deviate if they find a better path.*

1. In `countViaGhApi()`, insert `"--paginate"` into the args array passed to
   `Bun.spawnSync`.
2. Change the return statement from `parseInt(stdout)` to the
   `split("\n").reduce(...)` sum pattern from `hasCodexSubmittedReview()`.
3. Add `--paginate` to the `gh api` commands in the two template/skill files.

## Scope

**In scope:** The four changes listed above (one code fix with two parts, two
documentation fixes).

**Out of scope:** Adding pagination to `isPrMerged()` or `getPrVerification()`
(these hit single-object endpoints that do not paginate). Adding tests (no test
infrastructure exists for these shell-spawning functions).

**Related:** task-e7b50cc7 (completed) established the `--paginate` + sum pattern
in `hasCodexSubmittedReview()`.
