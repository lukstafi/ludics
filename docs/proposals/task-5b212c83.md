# Proposal: Attach review artifacts to retrospective file chronologically

**Task:** task-5b212c83
**Effort:** medium

## Goal

Preserve the full content of review files from `.peer-sync/reviews/` in the retrospective JSON so they survive worktree cleanup. Currently `extractVerdicts()` only records metadata (round, type, verdict, reviewer) but discards the review body. The review content -- especially final REQUEST_CHANGES reviews -- is high-value for whoever picks up the work next.

## Acceptance Criteria

- During retrospective collection, read all review files from `.peer-sync/reviews/`
- Attach them to the retrospective JSON as a `reviews` array field (chronologically ordered)
- Each entry includes: `round`, `type` ("review" | "plan-review"), `reviewer`, `verdict`, and `content` (full markdown body)
- Order by round number, then by type (plan-review before review at same round), then alphabetically by reviewer
- Reviews survive worktree cleanup via the retrospective file
- The `process-suggestions` skill can optionally reference review content for richer follow-up tasks

## Context

### Where retrospectives are collected

- **`src/retrospective.ts`** -- the entire retrospective pipeline lives here
  - `extractVerdicts()` (line ~255): already reads `.peer-sync/reviews/` and parses filenames + verdicts, but only returns `RetrospectiveVerdict` (no content)
  - `collectAndWriteRetrospective()` (line ~433): primary collector, calls `extractVerdicts()` at line ~490
  - `RetrospectiveData` interface (line ~49): defines the JSON schema, currently has `verdicts: RetrospectiveVerdict[]` but no full-content field

### Review file naming patterns

Files in `.peer-sync/reviews/`:
- `round-N-<agent>.md` -- normal review round (e.g. `round-1-reviewer.md`)
- `plan-merge-N-<agent>.md` -- plan-merge review (e.g. `plan-merge-0-reviewer.md`)

### Verdict parsing

`parseVerdictFromContent()` (line ~294) already reads file content to detect APPROVE/REQUEST_CHANGES. The content is available but discarded after verdict extraction.

## Approach

### 1. Add `RetrospectiveReview` interface

```typescript
export interface RetrospectiveReview {
  round: number;
  type: "review" | "plan-review";
  reviewer: string;
  verdict: "approve" | "request_changes" | "timeout";
  content: string;
}
```

### 2. Create `extractReviews()` function

Refactor from `extractVerdicts()` -- same file-reading logic but returns full content. The existing `extractVerdicts()` can remain for backward compatibility or be refactored to delegate to `extractReviews()`.

The function reads each `.md` file from the reviews directory, parses the filename for round/type/reviewer, calls `parseVerdictFromContent()` for the verdict, and includes the full file content. Sort by `(round, type, reviewer)`.

### 3. Add `reviews` field to `RetrospectiveData`

Add `reviews: RetrospectiveReview[]` to the interface and populate it in `collectAndWriteRetrospective()`. The `collectRetrospectiveFallback()` path won't have a `peerSyncDir`, so it gets an empty array.

### 4. Keep `verdicts` for backward compatibility

The existing `verdicts` field stays unchanged. The new `reviews` field is the superset with content included.

## Scope

- **In scope:** `src/retrospective.ts` -- new interface, new extraction function, wiring into both collectors
- **Out of scope:** Changes to `process-suggestions` skill (the acceptance criterion says "optionally" -- that can be a follow-up). No changes to the peer-sync review-writing logic itself.
- **Risk:** Review files could be large; no truncation is proposed since they are human-authored summaries, typically under 2KB each.
