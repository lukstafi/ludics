# Proposal: Add --restart-t3code flag to ludics init

**Task:** task-44e0e906
**Effort:** small (3 lines flag parsing + ~12 lines restart logic)
**Confidence:** high

## Summary

Add an opt-in `--restart-t3code` flag to `ludics init` that stops and restarts the t3code server, so that after updating t3code code (e.g., `git pull` in `~/t3code-ludics`) the running server picks up the new code without a manual stop/start cycle. The flag is opt-in because restarting kills active agent sessions.

## Implementation Details

Three changes to `src/init.ts`, no other files affected.

### Change 1: Import (line 8, after existing imports)

Add import of `stopServer` and `ensureServer` from `./t3code/server.ts`:

```ts
import { stopServer, ensureServer } from "./t3code/server.ts";
```

Both functions are already exported (server.ts lines 209 and 360). Their signatures:

- `ensureServer(options?: EnsureServerOptions): Promise<T3CodeServerRecord>` -- finds a port, spawns, waits for health check
- `stopServer(options?: EnsureServerOptions): Promise<boolean>` -- WAL checkpoint, SIGTERM/SIGKILL, cleans up server.json

### Change 2: Flag parsing (line 22, after `noTriggers`)

```ts
const restartT3code = args.includes("--restart-t3code");
```

This follows the existing pattern at lines 20-22 where `--no-hooks`, `--no-dashboard`, and `--no-triggers` are parsed.

### Change 3: Restart block (after step 8 / dashboard block, before step 9 / triggers)

Insert between the closing brace of step 8 (line 77) and the comment for step 9 (line 79):

```ts
// 8b. t3code server restart (opt-in)
if (restartT3code) {
  console.log("\n--- t3code server restart ---");
  try {
    const stopped = await stopServer();
    console.log(stopped ? "  stopped existing server" : "  no running server found");
    const record = await ensureServer();
    console.log(`  started t3code server on ${record.webUrl} (pid ${record.pid})`);
  } catch (err) {
    console.warn(`warning: t3code restart failed: ${err instanceof Error ? err.message : String(err)}`);
  }
}
```

Placing it after dashboard (step 8) is intentional: the dashboard may need t3code, so we restart t3code after dashboard setup but before triggers.

## Why No Other Files Need Changes

- `src/t3code/server.ts` -- `stopServer()` and `ensureServer()` are already exported with the exact signatures needed. `stopServer` gracefully returns `false` when no server is running; `ensureServer` handles port scanning, spawning, locking, and health-check waiting.
- `src/index.ts` -- the `init` subcommand doesn't list per-flag help text; flags are self-documenting via naming convention (`--restart-t3code` matches the `--no-*` pattern).

## Risk Assessment

- **Low risk:** The restart block is guarded by an opt-in flag, so default behavior is unchanged.
- **No new dependencies:** Uses only existing, well-tested server lifecycle functions.
- **Error handling:** Wrapped in try/catch with a `console.warn`, matching the pattern used by the dashboard restart block (lines 58-76).
