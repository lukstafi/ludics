# Proposal: Detect stalled slots and auto-nudge or restart agents

**Task:** task-428374b7
**Status:** in-progress
**Priority:** A

## Summary

Add self-healing capabilities to the orchestration system: detect when agents stall (peer-sync reports done but the turn lifecycle remains running/dispatched), send phase-aware nudge messages to recover stuck agents, force-settle after repeated failures, and auto-resume dead orchestrator processes from the keepalive loop. This eliminates the most common class of manual intervention required today.

## Key Code Touchpoints

### 1. Orchestration runner (`src/orchestration/runner.ts`)

- **`refreshAgentStatuses()`** (line 58): The main per-agent status refresh loop. Already reads peer-sync status, updates `AgentRuntimeState`, calls `updateTurnLifecycle()`, and invokes `detectAgentInconsistencies()`. The stall detection hook goes here, after line 100 (`detectAgentInconsistencies` call).

- **`detectAgentInconsistencies()`** (line 154): Currently emits a warning when `DONE_STATUSES.has(runtime.status) && (lc.state === "running" || lc.state === "dispatched")`. This is the exact condition we want to act on, not just warn about. The new `detectAndNudgeStalls()` will extend this warning into active recovery.

- **`pollUntilDone()`** (line 598): The main poll loop. Calls `refreshAgentStatuses()` on each tick (line 633), then checks `allAgentsDone()` (line 651). The stall detection/nudge function should be called after `refreshAgentStatuses()` and before `allAgentsDone()`.

- **`interruptAgent()`** (line 539): Writes an interrupt file via `writeInterrupt()` and dispatches `thread.turn.interrupt` via t3code. This is the force-settle mechanism for stalls that don't respond to nudging.

- **`withClient()`** (line 26): The pattern for t3code WebSocket operations. Takes a `T3CodeServerRecord` and a callback, auto-closes the client.

### 2. State interfaces (`src/orchestration/state.ts`)

- **`AgentTurnLifecycle`** (line 35): Needs three new fields: `stallDetectedAt: string | null`, `nudgeAttempts: number`, `lastNudgeAt: string | null`. These track stall detection state per-agent per-turn.

- **`AgentRuntimeState`** (line 58): No changes needed; it already holds `turnLifecycle` which will carry the new fields.

- **`OrchestrationConfig`** (line 68): Could hold stall thresholds, but initial implementation can use module-level constants for simplicity.

### 3. Phase definitions (`src/orchestration/phases.ts`)

- **`DONE_STATUSES`** (line 121): The set of status strings that indicate an agent has finished its phase work. Used in the stall condition: `DONE_STATUSES.has(status) && lc.state in ["running", "dispatched"]`.

- **`isAgentDone()`** (line 201): The authoritative done check. Importantly, it returns `false` when `lc.state` is "dispatched", "starting", or "running" (line 215-216). This is correct behavior -- but it means a stalled agent where the turn never settles will block phase transitions indefinitely without the proposed nudge/force-settle mechanism.

### 4. t3code thread send (`src/t3code/index.ts`)

- **`threadSend()`** (line 116): The existing implementation shows the dispatch pattern: fetch snapshot for thread metadata, build a `thread.turn.start` command with `messageId`, `role: "user"`, dispatch via `client.dispatchCommand()`. For nudging, we need a simplified version without `--wait` behavior (non-blocking).

- **`withClient()`** (line 20): Same pattern as runner.ts but in a different module. The runner already has its own `withClient` (line 26), so nudge dispatch should use the runner's version.

### 5. Keepalive path (`src/mag.ts`)

- **`magStart()`** (line 2170): When `magIsRunning()` is true (line 2191), runs the keepalive sequence: `ensureT3codeIfEnabled`, `maybeClearDoneSlots` (line 2208), `maybeFillEmptySlots` (line 2211), `maybeRecoverStuckStartup` (line 2214). The new `maybeResumeDeadOrchestrators()` slots in between `maybeClearDoneSlots` and `maybeFillEmptySlots`.

- **`maybeClearDoneSlots()`** (line 2128): The pattern to follow -- iterates `parseSlotBlocks()`, checks task status, acts on each slot. The new function follows the same iteration pattern but checks PID liveness instead of task status.

### 6. Slot resume (`src/slots/index.ts`)

- **`slotResume()`** (line 614): Already handles the full resume flow: validates persisted state, checks thread existence, terminates stale PIDs (line 703-725), resets `turnLifecycle` to null for all agents (line 730-731), clears `phaseDispatched` (line 733), restarts the orchestration process. This is exactly what `maybeResumeDeadOrchestrators()` should call.

## Refined 4-Part Implementation Plan

### Part 1: Stall detection and nudging in the poll loop

**New fields on `AgentTurnLifecycle`** (state.ts, line 35):
```typescript
stallDetectedAt: string | null;   // ISO timestamp of first stall detection
nudgeAttempts: number;             // count of nudge messages sent
lastNudgeAt: string | null;       // ISO timestamp of most recent nudge
```

**New constants** (runner.ts, top-level):
```typescript
const STALL_THRESHOLD_S = 180;           // 3 min: peer-sync done + lifecycle running
const DISPATCH_STALL_THRESHOLD_S = 300;  // 5 min: dispatched but never started
const NUDGE_COOLDOWN_S = 120;            // 2 min between nudge attempts
const MAX_NUDGE_ATTEMPTS = 2;            // force-settle after 2 failed nudges
```

**New function `detectAndNudgeStalls()`** (runner.ts):
- Called from `pollUntilDone()` after `refreshAgentStatuses()`, before `allAgentsDone()` check.
- For each participating agent:
  - Skip if `!lc` or `lc.state === "settled"` or `lc.state === "error"`.
  - **Running stall**: `DONE_STATUSES.has(runtime.status) && lc.state === "running" && age(lc.turnStartedAt) > STALL_THRESHOLD_S`.
  - **Dispatch stall**: `lc.state === "dispatched" && age(lc.dispatchedAt) > DISPATCH_STALL_THRESHOLD_S`.
  - On first detection: set `lc.stallDetectedAt = isoNow()`, emit `orchestration_stall_detected`.
  - If `lc.nudgeAttempts < MAX_NUDGE_ATTEMPTS` and cooldown elapsed:
    - Fetch snapshot to get thread metadata (runtimeMode, interactionMode).
    - Build nudge message: `"Your work for the ${state.phase} phase is complete. Stop and wait for further instructions."`
    - Dispatch `thread.turn.start` command (non-blocking, no wait).
    - Increment `lc.nudgeAttempts`, set `lc.lastNudgeAt`.
    - Emit `orchestration_nudge_sent`.
  - If `lc.nudgeAttempts >= MAX_NUDGE_ATTEMPTS` and stall persists:
    - Call `interruptAgent()` to force-settle.
    - Emit `orchestration_force_settle`.
- `persistState()` after any modifications.

**Post-nudge outcome logging** (in `refreshAgentStatuses()`, after `updateTurnLifecycle`):
- If `lc.stallDetectedAt` is set and `lc.state` transitions to `"settled"`:
  - Check if the latest thread message is from "assistant" (nudge got a response) -> `orchestration_nudge_settled_alive`.
  - Otherwise -> `orchestration_nudge_settled_dead` (t3code detected disconnect on send).
  - Clear stall fields (`stallDetectedAt = null`, `nudgeAttempts = 0`).

### Part 2: Dead orchestrator detection and auto-resume in keepalive

**New function `maybeResumeDeadOrchestrators()`** (mag.ts):
- Follows `maybeClearDoneSlots()` pattern: parse slot blocks, iterate active slots.
- For each slot with a task and `Mode=t3code`:
  - Read `readSlotState(slotNum)` to get `slotState.orchestration?.pid`.
  - Read `readOrchestrationState(slotNum)` to get current phase.
  - Skip if no orchestration state or `phase === "done"`.
  - Check PID liveness: `try { process.kill(pid, 0) } catch { dead = true }`.
  - If dead: call `slotResume(slotNum)`, emit `orchestration_auto_resume`.
  - Rate-limit: at most 1 resume per keepalive invocation to avoid thundering herd (keepalive runs every ~60s via cron).

**Call site**: Insert `await maybeResumeDeadOrchestrators()` after `maybeClearDoneSlots()` (line 2208) and before `maybeFillEmptySlots()` (line 2211).

### Part 3: Health check reporting

- In the health-check skill or dashboard flow view:
  - For each active slot, read orchestration state.
  - If any agent has `turnLifecycle.stallDetectedAt` set, report: slot number, agent name, stall duration, nudge attempts.
  - This is a read-only addition to existing reporting infrastructure.

### Part 4: Event logging

All events use the existing `emitEvent()` infrastructure (from `src/events.ts`):

| Event type | When | Key fields |
|---|---|---|
| `orchestration_stall_detected` | First detection of stall condition | slot, agent, phase, stallType ("running"/"dispatch") |
| `orchestration_nudge_sent` | Nudge message dispatched | slot, agent, phase, attempt |
| `orchestration_nudge_settled_dead` | Turn settled after nudge, no response | slot, agent |
| `orchestration_nudge_settled_alive` | Turn settled after nudge, got response | slot, agent |
| `orchestration_force_settle` | Force-interrupted after max nudges | slot, agent, attempts |
| `orchestration_auto_resume` | Keepalive resumed dead orchestrator | slot, task, deadPid |

## Risks and Mitigations

1. **Nudge starts new work**: The nudge message tells the agent to stop, but if the agent is actually alive and working, the nudge becomes a new user turn that might cause the agent to respond with additional output.
   - **Mitigation**: The nudge message is phase-aware ("Your work for the X phase is complete. Stop and wait.") -- it instructs the agent not to start new work. The poll loop will detect settlement normally.

2. **Race between nudge dispatch and natural settlement**: The agent might settle naturally between stall detection and nudge dispatch, causing a spurious user message on a completed turn.
   - **Mitigation**: Re-check snapshot state before dispatching the nudge. If the turn has settled in the interval, skip the nudge.

3. **Thundering herd on keepalive resume**: If multiple orchestrators crash simultaneously (e.g., t3code server restart), all would be resumed at once.
   - **Mitigation**: Rate-limit to 1 resume per keepalive invocation. With ~60s cron interval, 6 slots would recover in ~6 minutes, which is acceptable.

4. **False positive stall detection**: An agent might legitimately take longer than `STALL_THRESHOLD_S` to settle its turn after peer-sync reports done (e.g., writing large files, slow network).
   - **Mitigation**: The 3-minute threshold is generous (normal settlement takes seconds). The first action is a benign nudge, not a force-settle. Force-settle only happens after 2 failed nudges (~7+ minutes total).

5. **`slotResume` failure in keepalive**: If resume throws (e.g., missing threads), the keepalive loop should not crash.
   - **Mitigation**: Wrap `slotResume()` call in try/catch, emit an error event, and continue to the next slot.

## Dependencies

- No external dependencies.
- Relies on existing `interruptAgent()`, `slotResume()`, `emitEvent()`, and `withClient()` infrastructure.
- The `AgentTurnLifecycle` interface change is additive (new optional/defaulted fields), so it is backward-compatible with persisted state files.
