# Proposal: Dashboard tasks.html retrospective links + time-based filter

**Task**: task-322291a6
**Project**: ludics
**Date**: 2026-03-28

## Summary

Add two independent features to the tasks.html dashboard page:
1. Done tasks with retrospective files get a clickable "retrospective" link
2. A time-based filter (All / 30 days / 7 days / 24 hours) based on task file mtime

Both features require backend data enrichment in `src/dashboard.ts` and frontend rendering changes in `templates/dashboard/tasks.html`.

## Design

### Part 1: Retrospective links

**Backend changes (`src/dashboard.ts`)**

- Add `hasRetrospective: boolean` to `TasksTreeNode` interface (line 309).
- In `buildTaskNode()` (around line 524), after resolving the task, check:
  ```ts
  const hasRetrospective = task.isCompleted &&
    existsSync(join(harnessDir(), "retrospectives", `${task.id}.json`));
  ```
- Include `hasRetrospective` in the returned node object (line 546-557).
- For fallback nodes (line 509-521) and project nodes (line 584-595), set `hasRetrospective: false`.
- No new imports needed: `existsSync`, `harnessDir()`, and `join` are already imported.

**Frontend changes (`templates/dashboard/tasks.html`)**

- In `renderNode()` (line 290), after the `proposalLink` block (line 301-308), add:
  ```js
  if (node.hasRetrospective) {
      const retroLink = document.createElement('a');
      retroLink.textContent = 'retrospective';
      retroLink.href = `retrospective.html?task=${encodeURIComponent(node.id)}`;
      retroLink.target = '_blank';
      retroLink.rel = 'noopener noreferrer';
      row.appendChild(retroLink);
  }
  ```
- This uses the same `?task=TASK-ID` URL parameter that `retrospective.html` expects (line 173-174).

### Part 2: Time-based filter

**Backend changes (`src/dashboard.ts`)**

- Add `mtime: string | null` (ISO timestamp) to `TasksTreeNode` interface.
- Add `mtime: string` to `DashboardTask` interface.
- In `readDashboardTasks()` (line 355-386), after reading the file content, stat the file:
  ```ts
  const fileMtime = statSync(join(tasksDir, f)).mtime.toISOString();
  ```
  Include `mtime: fileMtime` in the pushed task object. `statSync` is already imported.
- In `buildTaskNode()`, propagate `mtime: task.mtime` into the node.
- For fallback nodes and project nodes, set `mtime: null`.

**Frontend changes (`templates/dashboard/tasks.html`)**

- Add filter bar HTML after `<h2>Tasks</h2>` (line 201):
  ```html
  <div class="filter-bar">
      <span>Filter:</span>
      <button class="filter-btn active" data-filter="all">All</button>
      <button class="filter-btn" data-filter="30d">Last 30 days</button>
      <button class="filter-btn" data-filter="7d">Last 7 days</button>
      <button class="filter-btn" data-filter="24h">Last 24 hours</button>
  </div>
  ```

- Add CSS for `.filter-bar` and `.filter-btn` (with `.active` and `:hover` states) in the `<style>` block.

- Add filter state management:
  - Read initial filter from `localStorage.getItem('tasks-filter')` (default: `'all'`).
  - On button click, save to localStorage, update active class, and re-render.
  - Global `currentFilter` variable tracks the active filter.

- Add `filterTree(nodes, cutoff)` function for recursive tree filtering:
  - `'all'` mode returns unfiltered tree.
  - For `'30d'`, `'7d'`, `'24h'`, compute a cutoff timestamp and recursively filter.
  - Task nodes pass if their `mtime >= cutoff` OR any descendant passes.
  - Project nodes pass if they have any passing children.
  - Nodes with `mtime: null` (project/fallback) are kept when they have passing children.

- In `renderTasksTree()`, apply `filterTree()` before rendering. Show "No tasks match filter" placeholder when the result is empty.

## Edge Cases

- Tasks without mtime (project nodes, fallback nodes) always pass if they have passing children.
- `statSync` adds minimal overhead since the file was just read by `readFileSync`.
- `existsSync` for retrospective check is cheap and already used extensively in the codebase.
- Filter persistence via localStorage avoids URL clutter and works across page navigations.
- When filter yields no results, display a placeholder message rather than empty space.
