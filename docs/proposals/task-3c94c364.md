# Proposal: Extract shared tile generator for dashboard filtered-task-list tiles

## Goal

Eliminate copy-paste duplication between the Needs Confirmation and Unanswered Questions dashboard tiles by extracting shared parameterized helpers in both the backend (TypeScript generator) and frontend (JS fetch/render).

## Acceptance Criteria

1. A single `generateFilteredTaskList(tasks, config)` function in `src/dashboard.ts` replaces both `generateNeedsConfirmation` and `generateUnansweredQuestions`. Each tile is expressed as a config object (filter predicate + extra-field list).
2. The two separate interfaces (`NeedsConfirmationTask`, `UnansweredQuestionsTask`) are replaced by a single generic type or `Record`-based output.
3. A single `fetchAndRenderTaskList({ jsonFile, listId, emptyText, renderItem })` function in `templates/dashboard/dashboard.js` replaces the duplicated fetch/render pairs. Each tile provides its own `renderItem` callback for tile-specific markup (action buttons for needs-confirmation, plain link for unanswered-questions).
4. The two `writeFileSync` calls at ~L959-962 use the shared generator with per-tile configs.
5. The HTML sections in `index.html` remain unchanged (they are already minimal and not worth abstracting for two instances).
6. No behavioral change: both tiles render identically before and after the refactor. JSON file names and structure stay the same.
7. All existing dashboard functionality (confirm/dismiss buttons, priority badges, fetch intervals) continues to work.

## Context

**Backend duplication** (`src/dashboard.ts`):
- `generateNeedsConfirmation()` (L495-506): filters `status === "needs-confirmation"`, maps to `{id, title, project, priority, created, relatesTo}`.
- `generateUnansweredQuestions()` (L508-517): filters `hasQuestions && !isCompleted`, maps to `{id, title, project, priority}`.
- Interfaces at L339-353; write calls at L959-962.

**Frontend duplication** (`templates/dashboard/dashboard.js`):
- `fetchNeedsConfirmation()` / `renderNeedsConfirmation()` (L506-547): fetch JSON, render `<li>` with priority badge + task link + source annotation + confirm/dismiss buttons.
- `fetchUnansweredQuestions()` / `renderUnansweredQuestions()` (L549-586): identical pattern, simpler `<li>` (no buttons, no source).

**HTML** (`templates/dashboard/index.html` L108-122): Two `<section>` blocks with heading + `<ul>` placeholder. Minimal, not worth abstracting.

## Approach

### Backend

1. Define a config type:
   ```ts
   interface FilteredTaskTileConfig {
     filter: (task: DashboardTask) => boolean;
     extraFields?: Array<"created" | "relatesTo">;
   }
   ```
2. Implement `generateFilteredTaskList(tasks, config)` that applies the filter and maps to a base shape `{id, title, project, priority}` plus any extra fields.
3. Define two config constants (one for needs-confirmation, one for unanswered-questions).
4. Replace the two generator calls and remove the old interfaces.

### Frontend

1. Implement `fetchAndRenderTaskList({ jsonFile, listId, emptyText, renderItem })`:
   - Fetches `CONFIG.dataPath + jsonFile`.
   - On success, calls `renderItem(task)` for each task to produce an `<li>` string.
   - On empty, shows `emptyText`.
   - Uses the existing innerHTML-diff pattern.
2. Replace `fetchNeedsConfirmation` / `renderNeedsConfirmation` with a call passing `renderItem` that includes action buttons.
3. Replace `fetchUnansweredQuestions` / `renderUnansweredQuestions` with a call passing a simpler `renderItem`.
4. Keep `confirmTask` / `dismissTask` unchanged (they are tile-specific action handlers, not part of the duplication).

### Migration

- Add shared helpers first, rewrite callers, then remove old code in a single commit.
- Run dashboard manually to verify both tiles render correctly.
