# Proposal: Fix brittle JSON handling in queue

**Task**: task-9d30442b  
**Title**: Fix brittle JSON handling in queue: type writeResult and parse alreadyQueued JSONL  
**Status**: ready  
**Effort**: small

## Goal

Eliminate two remaining fragile JSON construction patterns in the queue pipeline:

1. `writeResult` in `src/queue.ts` builds result files via template string interpolation, which risks malformed JSON if any field contains characters needing escaping (e.g. quotes, backslashes, newlines in output content).
2. `collectProjectsWithQueuedPreemption` in `src/tasks/sync.ts` uses a raw `includes('"action":"preempt"')` string pre-filter on raw JSONL content before parsing — while not strictly broken, it is inconsistent with the now-established pattern of parsing JSONL lines directly.

The `alreadyQueued` JSONL parsing in `tasksQueueElaborations` and `tasksQueuePreemptions` has already been fixed (via typed `Set<string>` approach); only `writeResult` and the pre-filter in `collectProjectsWithQueuedPreemption` remain.

## Acceptance Criteria

1. `writeResult` builds result JSON using a typed `Record<string, unknown>` and `JSON.stringify`, with no template string construction of JSON.
2. The result file content correctly serializes the output file contents as a JSON string value (not double-escaped), matching what callers expect when reading the result.
3. `collectProjectsWithQueuedPreemption` parses JSONL lines via `JSON.parse` without a raw-string pre-filter — all field checks are done on parsed objects.
4. All existing tests pass; no behavioral regressions in queue read/write round-trips.

## Context

- `writeResult` is in `src/queue.ts` lines 178–192. The current code calls `JSON.stringify(readFileSync(...))` to escape the output string, then splices it into a template string — correct but fragile: any future field addition risks a similar mistake.
- `collectProjectsWithQueuedPreemption` is in `src/tasks/sync.ts` around line 269. The `includes('"action":"preempt"')` pre-filter is a conservative guard (no false negatives) but inconsistent with the pattern established elsewhere (`queueHasPendingAction`, `tasksQueueElaborations`, `tasksQueuePreemptions`).
- The canonical correct pattern is demonstrated by `queueHasPendingAction` in `src/queue.ts` lines 115–132: read file, split on newlines, `JSON.parse` each non-empty line in a try/catch, check typed fields.

## Approach

### Fix 1: `writeResult` in `src/queue.ts`

Replace template string construction with typed record:

```typescript
export function writeResult(requestId: string, status: string, outputFile?: string): void {
  const dir = resultsDir();
  mkdirSync(dir, { recursive: true });
  const resultFile = join(dir, `${requestId}.json`);
  const timestamp = new Date().toISOString().replace(/\.\d{3}Z$/, "Z");

  const result: Record<string, unknown> = { id: requestId, status, timestamp };
  if (outputFile && existsSync(outputFile)) {
    result.output = readFileSync(outputFile, "utf-8");
  }
  writeFileSync(resultFile, JSON.stringify(result) + "\n");
  emitEvent({ event_type: "queue_result", source: "mag", scope: "queue", status, message: requestId });
}
```

Note: the output field is stored as a plain string value in the record; `JSON.stringify` handles escaping uniformly. The previous code used `JSON.stringify(readFileSync(...))` to produce an escaped string, then embedded it without quotes into the template — this was equivalent but error-prone. The new code is equivalent and safe.

### Fix 2: `collectProjectsWithQueuedPreemption` in `src/tasks/sync.ts`

Remove the `includes` pre-filter and check the parsed field directly:

```typescript
for (const line of queueContent.split("\n")) {
  if (!line) continue;
  try {
    const req = JSON.parse(line) as Record<string, unknown>;
    if (req.action !== "preempt") continue;
    const qTask = String(req.task ?? "");
    const project = readTaskProjectName(tasksDir, qTask);
    if (project && priProjects.includes(project)) {
      projects.add(project);
    }
  } catch {
    // skip malformed queue lines
  }
}
```

This is the only change: replace `if (!line.includes('"action":"preempt"')) continue;` with `if (req.action !== "preempt") continue;` (moved inside the try block, after parse). Behavior is identical for valid JSONL; malformed lines are already handled by the catch.
