# Proposal: Simplify enterPhase skip-done guard to use isAgentDone directly

**Task**: task-4f91b925
**Project**: ludics

## Goal

Deduplicate validation logic in `isAgentDone()` and remove the redundant inline fingerprint staleness check from `enterPhase()`. This is a pure refactor with no behavior change: the same freshness gate and artifact validation run in both code paths today, but `enterPhase` duplicates the fingerprint check that `isAgentDone()` already performs.

## Acceptance Criteria

1. **Extract `validateDoneStatus` helper** in `src/orchestration/phases.ts`:
   - A private function that checks `DONE_STATUSES.has(runtime.status)`, then `hasRequiredArtifact(state, agent)`, emitting an `orchestration_warning` event on missing artifact, returning boolean.
   - Both the null-lifecycle branch (line 214) and the settled branch (line 261) of `isAgentDone()` delegate their artifact-validation + warning-emit blocks to this helper.

2. **Simplify `enterPhase` skip-done guard** in `src/orchestration/runner.ts` (lines 497-509):
   - Remove the inline `statusFileFingerprint` comparison and `isStale` variable.
   - Replace with a direct `isAgentDone(state, agent)` call: if it returns true, `continue`; otherwise fall through to dispatch.
   - The `agentStatus === currentPhaseDone || agentStatus === "done"` outer guard remains (performance: avoids calling `isAgentDone` for agents in non-done statuses).

3. **All existing tests pass** (`phases.test.ts`, `runner.test.ts`) with no new test cases needed.

4. **Net line reduction**: roughly 12-15 lines removed across the two files.

### Why the inline check is redundant

In `enterPhase`, `turnLifecycle` is always null at this point (it is set later at line 525, after dispatch). So `isAgentDone()` always takes the null-lifecycle branch, which performs the identical fingerprint comparison at lines 222-225. The `enterPhase` guard at lines 500-501 is therefore dead logic -- `isAgentDone` will return false for stale fingerprints regardless.
