# Proposal — gh-ludics-502: TEST_COMMAND substitution + bundled OCaml/Dune fixes

## Goal

Wire a computed `TEST_COMMAND` template variable into orchestration skills, substitute it for the hardcoded `bun test` in the coder/reviewer baseline steps, and land the adjacent Dune-PATH `test_command` config entries plus a macOS `head -n -<N>` gotcha note as separately-attributable commits in a single PR. The OCANNL `.expected` config-banner discipline lands as a small companion PR to `ahrefs/ocannl/AGENTS.md`.

## Context

Auto-filed from gh-ocannl-203 retro: `pair-coder-plan.md` and `pair-reviewer-gather.md` instruct agents to run `bun test` to record the baseline, which silently miscovers on Dune projects. The `test_command` field on `ProjectConfig` already exists (consumed by `src/health.ts`), and `buildContext` in `src/orchestration/skills.ts` already auto-injects every string project field as `PROJECT_<KEY>`. The fix is mostly a small computed-variable plumbing change and two skill template substitutions. Bundling the four resolved concerns from the elaboration's question block lets the test-health "Dune-PATH" cohort (seven OCaml projects whose nightly health is perpetually red because their non-opam shell can't find `dune`) self-heal at the same merge: setting `test_command: "eval $(opam env) && dune runtest"` for each repairs both the orchestration baseline step and the nightly health runner. gh-ludics-504 (`bun test 2>&1 | tail -40` plan-time visibility) is assumed merged when this PR starts; if not, rebase.

## Approach

Touchpoints, all confirmed by reading the code:

- **`src/orchestration/skills.ts:383–431`** — `result: Record<string, string>` is the central context object. Add `TEST_COMMAND: testCommandFor(_projectEntry, state.projectDir)` at the same level as `UPSTREAM_REPO` (set just below in the same record). The helper computes `(_projectEntry?.test_command?.trim() || null) ?? detectTestCommand(state.projectDir) ?? "bun test"`. The trailing `"bun test"` keeps the safety net for projects without dune-project / bun.lockb / package.json `test` script / Makefile `test:` target — same behaviour as today's hardcoded literal, just now overridable.
- **`src/health.ts:28`** — `detectTestCommand(projectPath: string): string | null` is already exported; just import it. No signature change.
- **`src/orchestration/skills.test.ts`** — add two test cases under the existing `describe("skills", ...)` block in the same style as the existing `buildSkillContext: ...` tests (lines 214–263). The test must materialize a temp dir with a `dune-project` file (or a stubbed `_projectEntry` with `test_command` set) and assert the `TEST_COMMAND` field on the returned context. Forbid: introducing a structural pinning test for the entire context shape.
- **`skills/orchestration/pair-coder-plan.md:9`** — `run \`bun test\`` → `` run `{{TEST_COMMAND}}` ``.
- **`skills/orchestration/pair-reviewer-gather.md:11`** — `Run \`bun test\`` → `` Run `{{TEST_COMMAND}}` ``.
- **`config.yaml:27`** (harness, in `lukstafi/self-improve`) — fix `test_commaand` → `test_command` (or delete the line; Bun is auto-detected). Add `test_command: "eval $(opam env) && dune runtest"` to each of the seven OCaml entries listed in AC5. The implementer should verify locally (one of the OCaml project paths) that the chosen invocation actually puts `dune` on PATH; if `eval $(opam env)` alone doesn't work in the test-health subprocess shell, fall back to `bash -lc '...'`.
- **`skills/worker-conventions.md`** — insertion point: under the existing `## Manual-Smoke Evidence` → `### Hygiene` subsection (line ~130), or append a small `### macOS notes` subsection. The implementer picks; the AC pins only the content, not the heading.

**Placement decision for the OCANNL `.expected` banner discipline (commit/PR 5).** Picking option (c): companion PR to `ahrefs/ocannl/AGENTS.md` (verified to exist upstream via `gh api repos/ahrefs/ocannl/contents/AGENTS.md`). Rationale: (a) is unavailable — ludics has no per-project memory convention in-repo (no `mag/memory/projects/`, no `docs/projects/`), and inventing the convention for a one-off note is over-scoped. (b) `docs/swe-textbook.md` exists in ludics but is for filter-rejected workflow-discipline know-how, not project-specific snapshot conventions. (c) is the cleanest functional home: OCANNL coders read `AGENTS.md` when working in that repo, and the discipline is OCANNL-specific (the banner literal `ocannl_log_level` only fires in that codebase). The cost of (c) is one extra PR — small, since the content is two paragraphs and the AGENTS.md file already exists. The user's "single PR for the concerns" framing applies to the ludics-side concerns; cross-repo guidance is materially different and lives where it applies.

**Out of scope.**

- gh-ludics-504 (plan-time `tail -40` visibility) — assumed merged at PR start; rebase if not.
- Coordination machinery between this PR and the OCANNL companion PR (no shared state, no ordering constraint).
- Spin-off tasks for any of the four concerns — the resolution explicitly forbids them.
- Updating `docs/orchestration-patterns.md` (which mentions `bun test` doctrinally) — leave as the canonical Bun-flavoured example; per-project override now carries the variation.
- Generalizing to non-test commands (`dune build @check` as a pre-edit smoke variant) — separate concern, file as a follow-up issue if it becomes load-bearing.
- Structural pinning tests for `buildContext`'s full shape — only the new `TEST_COMMAND` branch is in scope for the regression test.
