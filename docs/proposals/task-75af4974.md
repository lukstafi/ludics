# Federation v2: Complete Migration (Phases 4-5)

## Goal

Complete the Federation v2 migration. Slices 1-5 (Phases 1-3) implemented the HTTP transport layer, converted heartbeats/intents/signals to HTTP, and removed `statePull()` from worker and federation-tick paths. This proposal covers:

1. **Reviewer audit** of commits `bb1287b..6255afb` for stale-after-sync-removal bugs and incomplete migration paths.
2. **Phase 4**: Remove all remaining file-based cross-node sync code.
3. **Phase 5**: Reduce git commits to 6h + shutdown + handoff cadence.
4. **Worker writes via HTTP**: Redirect journal, event, orchestration-state, task-file, and slots.md updates from workers through HTTP to the controller.

After completion: workers never write to the harness directory. All cross-node coordination is HTTP. Git commits happen only at health-check (every 6h), controller shutdown, and controller handoff.

## Acceptance Criteria

- `src/worker-signal.ts` is deleted. No call sites remain.
- `src/slot-intents.ts` is deleted. No call sites remain.
- `resolveSlotsMd()` and `resolveAppendOnly()` are removed from `src/state.ts`. No merge conflict resolution logic remains.
- `statePush()` in `src/state.ts` is simplified: no squash-rebase-push dance, no conflict resolution.
- `SSH remotePing()` is removed from `src/remote.ts`. The file retains only `isRemoteMachine()`.
- `federation/heartbeats/`, `federation/slot-intents/`, and `worker-signals/` directories are removed from the harness and gitignored.
- `journalAppend()` detects worker context and forwards to controller via HTTP (`POST /api/federation/journal`).
- `emitEvent()` detects worker context and forwards to controller via HTTP (`POST /api/federation/event`).
- `persistState()` in `src/orchestration/state.ts` detects worker context and forwards via HTTP (`POST /api/federation/orchestration-state`).
- Task file updates from workers (`updateFrontmatterField()` on orchestration completion) go via HTTP (`POST /api/federation/task-update`).
- `stateCommit()` call sites in `src/slots/index.ts` (9 locations) are converted to `stateMarkDirty()`. Actual commits happen only at health-check, shutdown, and handoff.
- No regressions in the existing test suite (`bun test`).
- Dashboard slot terminals continue rendering (the stale-machine-field bug from Slice 3-4 is fixed if still present).

### Known Bug: Stale Machine Field After Sync Removal

After Slices 3-4 removed `statePull()` from worker paths, the `machine` field in slots.md stopped being refreshed on the worker side. The dashboard renders slot terminals based on `machine`, so when the field goes stale (returns `null` on resolution), terminal blocks stop rendering.

**Root cause**: The worker no longer pulls updated state. The machine field written in slots.md reflects the last controller-side write; if the slot was assigned while the worker was online and the assignment hasn't been re-pushed, the field may be absent from the worker's view.

**Fix direction**: With Phase 4 complete, workers no longer read slots.md at all — they query `GET /api/federation/slots` on the controller. The machine field is always fresh on the controller. The dashboard, which runs only on the controller, reads slots.md locally and is never stale.

**Reviewer audit task**: Scan `bb1287b..6255afb` for other cases where removed `statePull()` calls left stale reads. Focus on:
- Any code path that reads `slots.md` on a worker machine after Slices 3-4.
- Any code path that reads `federation/heartbeats/` or `worker-signals/` on a worker after Slices 3-4.

### Design Decisions (Confirmed by User)

1. **Pull model**: Workers poll controller every 60s; no worker HTTP server needed.
2. **Controller URL**: Derived from `config.yaml` federation machines + dashboard port. `resolveControllerCandidates()` (added in `b0ab7d8`) handles this.
3. **Workers clone state repo**: Workers still have a local state repo clone for `config.yaml` access. After Phase 4, this is the only reason they need it.
4. **Commit cadence**: Every 6h + controller shutdown + controller handoff. `stateMarkDirty()` + `stateCommit()` at health-check.
5. **Crash recovery**: Controller crash with lost state blocks on user confirmation. Recovery via PR/issue re-scan is future work.

### Phase 4: Remove File-Based Cross-Node Sync

**4a. Add missing HTTP endpoints to dashboard-server.ts / federation-http.ts**

Wire these server-side handlers (all guarded by `checkAuth()`):
- `POST /api/federation/journal` → append entry to journal/YYYY-MM-DD.md
- `POST /api/federation/event` → append to journal/events.jsonl
- `POST /api/federation/orchestration-state` → write orchestration/slot-N.json
- `POST /api/federation/task-update` → call `updateFrontmatterField()` on task file
- `GET /api/federation/task/:id` → return task file content
- `GET /api/federation/orchestration-state/:slot` → return orchestration state JSON
- `POST /api/federation/slot-update` → merge runtime section into slots.md (Session Started, Terminals, Runtime, Git)

Add corresponding client functions to `federation-http.ts` (or a new `src/federation-client.ts`).

**4b. Make journalAppend() and emitEvent() HTTP-aware**

In `src/journal.ts` and `src/events.ts`, add:
```typescript
import { federationIsController, federationEnabled } from "./federation.ts";
```
If `federationEnabled() && !federationIsController()`, call the HTTP endpoint instead of writing locally. Keep local write as fallback if HTTP fails (best-effort).

**4c. Make orchestration state HTTP-aware**

In `src/orchestration/state.ts`, wrap `persistState()` with the same worker-detection pattern. For state reads (`loadState()`), use `GET /api/federation/orchestration-state/:slot` when on worker.

**4d. Task file updates from workers via HTTP**

In `src/orchestration/runner.ts`, wrap the `updateFrontmatterField()` calls with worker-detection. Use `POST /api/federation/task-update`. For task file reads, use `GET /api/federation/task/:id`.

**4e. Remove dead code**

- Delete `src/worker-signal.ts`. Remove all imports and call sites.
- Delete `src/slot-intents.ts`. Remove all imports and call sites (including the `writeSlotIntent()` call inside `federation-http.ts handleIntent()`).
- In `federation-http.ts handleIntent()`: instead of writing an intent file, call the slot action handler directly (or enqueue it for the next keepalive cycle via an in-memory queue on the worker — simpler: just write a local ephemeral file that doesn't get committed).
- Remove `resolveSlotsMd()` and `resolveAppendOnly()` from `src/state.ts`.
- Simplify `statePush()`: remove the squash-rebase-merge logic. Replace with a direct `git pull --rebase && git push`.
- Remove `remotePing()` from `src/remote.ts`. Update any call sites to use HTTP reachability check instead (try `GET /api/federation/leader` with short timeout).
- Remove `federation/heartbeats/`, `federation/slot-intents/`, and `worker-signals/` from the harness directory. Add to `.gitignore` if needed.
